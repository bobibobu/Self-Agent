# A2A 协议（Agent2Agent）

> 让 Agent 之间互相发现与协作的开放标准。本模块讲清楚 A2A 是什么、与 MCP 的区别、怎么用。

---

## 一、A2A 是什么？

**一句话**：Agent 间的通信协议，让独立 Agent 互相发现并协作。

类比：MCP 是「USB-C 工具接口」（agent↔tool），A2A 是「HTTP」（agent↔agent）。

```
┌──────────┐    A2A     ┌──────────────┐
│ 本 Agent  │ ←────────→ │ 翻译 Agent    │
│          │  发现+调用  │ 分析 Agent    │
└──────────┘            │ 写作 Agent    │
     ↑                  └──────────────┘
     │ 也被外部调用
     ▼
┌──────────────┐
│ 其他系统      │
└──────────────┘
```

**核心原则**：Agent 间是「不透明对等体」——共享输入输出，**不共享**内部工具、记忆、状态。
这保证了解耦：你不需要知道对方用什么框架、什么 LLM。

## 二、协议要点（a2a-sdk 1.1.x / v1.0 协议）

| 概念 | 说明 |
|---|---|
| **Agent Card** | 能力清单，在 `/.well-known/agent-card.json` 暴露 |
| **Task** | 工作单元，状态机：submitted→working→completed |
| **Message** | 一轮对话，含 role 和 Parts |
| **Part** | 内容块（text / data / file） |
| **传输** | JSON-RPC 2.0 over HTTP + REST 端点 |

### 关键端点（本 Agent 暴露的）

| 端点 | 方法 | 用途 |
|---|---|---|
| `/.well-known/agent-card.json` | GET | 发现（返回 Agent Card） |
| `/message:send` | POST | 发送消息 |
| `/tasks` | GET | 列出任务 |
| `/tasks/{id}:cancel` | POST | 取消任务 |

## 三、两个方向

### Server：暴露本 Agent（`app/a2a/server.py`）

```python
mount_a2a(app)  # 把 A2A 路由挂到 FastAPI
```

挂载后，本 Agent 可被任何 A2A 客户端发现和调用。
`SelfAgentExecutor`（`app/a2a/executor.py`）把 `run_agent` 包装成 A2A 任务执行器。

独立运行（作为单独的 A2A agent 进程）：
```bash
python -m app.a2a.standalone --port 8001
```

### Client：调用外部 Agent（`app/a2a/client.py`）

```python
from app.a2a.client import call_remote_agent
reply = await call_remote_agent("http://other-host:8001", "翻译这段话")
```

还封装成 LangChain 工具 `delegate_to_agent`，LLM 可自主决定何时委托外部 Agent：
```python
@tool
async def delegate_to_agent(base_url: str, message: str) -> str:
    """委托任务给另一个 A2A Agent。"""
    return await call_remote_agent(base_url, message)
```

## 四、多 Agent 协作场景

本 Agent 既能：
- **被调用**：其他系统/Agent 通过 A2A 与它对话
- **调用别人**：通过 `delegate_to_agent` 委托专业 Agent

典型流程：
```
用户："帮我翻译这段话并总结"
  ↓
本 Agent：识别需要翻译 → delegate_to_agent("http://translator:8001", 原文)
  ↓
翻译 Agent：返回译文
  ↓
本 Agent：拿到译文 → 整合总结 → 回复用户
```

## 六、版本说明

a2a-sdk 1.1.x 使用 **v1.0 协议**，与早期 v0.3 有差异：
- Agent Card 路径：`/.well-known/agent-card.json`（非 `agent.json`）
- 消息类型：protobuf 风格（`Part(text=...)`）非 pydantic
- 端点：REST 风格（`/message:send`）非纯 JSON-RPC

本模块按 1.1.x 实际 API 实现。

## 七、面试要点

**Q: A2A 和 MCP 的本质区别？**
A: MCP 是 agent↔tool（调用工具，工具是被动的），A2A 是 agent↔agent（两个有自主决策能力的 Agent 协作）。A2A 的 Agent 有自己的 LLM、记忆、工具，是"对等"的；MCP 的工具没有。互补：一个 Agent 可同时是 A2A server（被调用）+ A2A client（调别人）+ MCP client（用工具）。

**Q: 为什么 Agent 间要"不透明"？**
A: 解耦与异构。你不需要知道对方用 LangGraph 还是 AutoGen、用 GPT 还是 Claude。只要遵守 A2A 协议（输入消息、输出回复），任意实现都能互通。这就像 HTTP 让任意服务器互通一样。

**Q: delegate_to_agent 作为工具有什么风险？**
A: 主要风险是**信任与安全**——把任务委托给外部 Agent，无法保证其输出质量或安全。生产应加：超时控制、输出校验、白名单（只委托可信 Agent）、审计日志。当前实现已有超时（60s）和错误兜底。
