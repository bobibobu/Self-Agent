# 第 1 章：编码 Agent 的共同骨架

> 在拆解具体项目之前，先看清所有编码 Agent 共享的骨架。看懂这个，后面四家的差异都只是「在这个骨架上换零件」。

---

## 1.1 编码 Agent vs 聊天机器人

Phase 10 之前的 Self-Agent 是个聊天机器人。区分点：

| 能力 | 聊天机器人 | 编码 Agent |
|---|---|---|
| 读文件 | 不能 | 能（需禁闭） |
| 改文件 | 不能 | 能（需审批） |
| 跑命令 | 不能 | 能（需沙箱） |
| 不可逆操作 | 无 | 有 |

一旦 Agent 能改文件、跑命令，就**必须**补上安全层（第 6 章详讲）。所以「编码 Agent」和「带安全层的 Agent」几乎是同义词。

---

## 1.2 核心认知：harness 包裹 model

来自 VILA-Lab 对 Claude Code 的逆向分析，最重要的结论是：

> **loop 本身很简单，真正的复杂度在 harness 的上下文管理、权限门、执行、恢复、审计。**

模型只是**决策点**——一个纯函数「输入上下文 → 输出下一步动作」。真正难的是包围模型的工程外壳（harness）。

```
┌─────────────────────────────────────────┐
│  harness（工程外壳）                       │
│  ├─ 上下文管理（把相关代码塞进 LLM）        │
│  ├─ 权限门（危险操作前问人/圈边界）         │
│  ├─ 执行引擎（真的读写文件、跑命令）        │
│  ├─ 恢复逻辑（出错怎么办）                  │
│  └─ 审计（记录干了什么）                    │
│         ↓ 包裹                            │
│    model（决策点）                        │
│    本质就是一个 while 循环：               │
│    读上下文 → 决策 → 调工具 → 观察 → 重复  │
└─────────────────────────────────────────┘
```

---

## 1.3 while 循环：所有编码 Agent 的内核

不管外面包了什么，内核都是同一个循环：

```python
while True:
    context = build_context(...)              # 决定给模型看什么
    action = model.decide(context)            # 模型决策
    if action.is_terminal:                    # 不调工具就结束
        break
    if permission_gate.block(action):         # 权限门
        continue
    result = executor.run(action)             # 真的执行
    observe(result)                           # 观察，进下一轮
```

Claude Code 的循环就是这样的极简 while。Aider、Cline、Self-Agent 内核都是这个。**没有花哨的图、复杂的状态机**——那些都是为了让这个循环跑得稳而加的外壳。

## 1.4 四个维度的差异全在 harness

各家的差异，本质是 harness 四个零件的不同选择：

| 维度 | 决定什么 | Self-Agent 怎么选 |
|---|---|---|
| **上下文管理** | 每次给模型看什么代码 | 检索 + 上下文压缩 |
| **权限/安全** | 危险操作怎么处理 | 工作区禁闭 + 审批 + 沙箱 |
| **执行引擎** | 怎么真的改文件/跑命令 | 文件工具 + Shell 工具（shlex，无 shell=True） |
| **改代码方式** | 模型怎么表达「改哪里」 | edit_file（精确替换） |

后面四章（Claude Code/Aider/Cline/Cursor）拆解的就是这四个零件的具体实现。

## 1.5 编码 Agent 面对的三个共同难题

不管哪家，都要回答这三个问题：

### 难题①：大仓库怎么不爆 token

几十万行代码不可能全塞进 LLM。怎么让 agent「看到」相关代码又不被淹没？

- **Aider**：tree-sitter 解析 + 图排序选最相关定义（repo-map，第 3 章）
- **Cursor**：整个代码库 embedding 化做语义检索（第 5 章）
- **Self-Agent**：grep/glob + 向量检索 + 上下文压缩
- **Claude Code/Cline**：会话级，靠模型自己用工具探索

### 难题②：怎么让 agent 放手干又不闯祸

agent 要试错（改了跑测试、失败再改），但试错不能造成不可逆破坏。

- **Claude Code**：走向沙箱化，「圈一块地随便干」（第 2 章）
- **Cline**：Plan/Act 分离 + 可选 autopilot（第 4 章）
- **Self-Agent**：三层安全最完整（第 6 章）

### 难题③：长任务怎么不迷失

「重构这个模块」这类任务，agent 走到第七八步就忘了最初目标。

- **Aider**：Architect/Editor 双模型分工（第 3 章）
- **Cline**：Plan 模式先规划（第 4 章）
- **Self-Agent**：update_plan 任务计划（外部记事板）
