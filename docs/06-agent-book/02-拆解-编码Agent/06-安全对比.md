# 第 6 章：横向对比 —— 四家怎么做安全

> 把 Claude Code、Aider、Cline、Cursor 的安全设计拉到一张表上对比，看清楚编码 Agent 安全设计的全貌和演进方向。

---

## 6.1 安全的四道防线

回顾全书第 8 章，编码 Agent 的安全可以分四道防线：

| 防线 | 管什么 | 实现手段 |
|---|---|---|
| **路径禁闭** | agent 能碰哪些路径 | Workspace.resolve() 检查归属 |
| **审批闸门** | 危险操作要不要问人 | interrupt() + 风险分级 |
| **执行隔离（沙箱）** | 同意后最多能造成多大破坏 | bubblewrap/Landlock/VM |
| **可回滚** | 出错了能救回来 | git commit / checkpoint |

不是每家都四道全做。各家按自己的定位取舍。

---

## 6.2 四家安全设计对照

| 防线 | Claude Code | Aider | Cline | Cursor | Self-Agent |
|---|---|---|---|---|---|
| **路径禁闭** | ✓ | ✗（靠 git） | ✓（IDE 沙箱） | ✓（IDE） | **✓ resolve+归属** |
| **审批闸门** | ✓（93% 同意率） | ✗ | ✓（+autopilot） | ✓ | **✓ 四档策略** |
| **执行隔离** | 走向沙箱化 | ✗ | ✗（靠 IDE） | ✗（靠 IDE） | **✓ bubblewrap/Landlock** |
| **shell 注入防护** | ✓ | — | ✓ | — | **✓ shlex，无 shell=True** |
| **可回滚** | 有 | **✓ git 自动 commit** | 有 | 有 | ✓ checkpointer |

### 解读

- **Self-Agent 是唯一四道全做且最完整的**：路径禁闭 + 四档审批 + bubblewrap/Landlock 沙箱 + shlex 防注入 + checkpointer
- **Aider 走「可回滚优先」路线**：不做前几道，靠 git 兜底——信任 git 的可回滚性
- **Claude Code 正在向 Self-Agent 已经做到的方向演进**：从审批走向沙箱化
- **Cline/Cursor 依赖 IDE 的隔离**：在 VS Code 扩展形态下，IDE 本身提供了一定隔离

## 6.3 ★ 两条安全哲学

四家其实分成两条哲学路线：

### 路线 A：前置拦截（Self-Agent、Claude Code 早期）

「**不让坏事发生**」——在操作执行前就拦住。

- 工作区禁闭挡路径越界
- 审批闸门挡未授权操作
- 沙箱挡越界访问

优点：坏事根本发生不了。缺点：认知负担重（93% 同意率问题）、限制 agent 灵活性。

### 路线 B：事后可回滚（Aider）

「**让坏事能 undo**」——允许 agent 自由试错，但出错了能回滚。

- git 自动 commit 每次修改
- 失败了 `git reset`

优点：agent 灵活、无打断。缺点：有些事 git 救不回来（如 `rm -rf` 删了未 commit 的、网络外泄）。

### Self-Agent 的选择

Self-Agent **两条都做，以前置为主**：
- 前置：工作区禁闭 + 审批 + 沙箱（路线 A）
- 事后：checkpointer 可恢复 +（编码场景可加）git 兜底（路线 B）

这是最保守的组合——因为 Self-Agent 定位企业级，宁可多拦。

## 6.4 沙箱方案横向对比

针对「执行隔离」这道防线，业界有几种方案：

| 方案 | 隔离机制 | 冷启动 | 定位 | 谁用 |
|---|---|---|---|---|
| **bubblewrap/Landlock** | Linux 内核原生（命名空间 + LSM） | 无（本地） | OS 级禁闭，无网络开销 | **Self-Agent** |
| **E2B** | Firecracker microVM | ~150ms | 远程托管，专做不可信代码执行 | 云端 agent |
| **Daytona** | 环境式 | 中等 | 灵活开发环境 | 云端 agent |
| **Modal** | 容器式 | 快 | serverless、GPU | 云端 agent |
| **IDE 隔离** | VS Code 扩展沙箱 | 无 | 扩展级 | Cline、Cursor |

### Self-Agent 选 bubblewrap/Landlock 的理由

1. **OS 级最彻底**：内核原生机制，比应用级沙箱硬
2. **无冷启动**：本地执行，不像 microVM 要启动
3. **无网络开销**：不像远程沙箱要传数据
4. **Claude Code 也在向这个方向走**：业界共识是 OS 级 > 应用级

### 已知限制（诚实）

- Landlock 后端**只管文件系统不限制网络**（网络隔离靠 bubblewrap 的 --unshare-net）
- 两个后端都**不做 syscall 过滤**，未防提权类攻击
- **Windows 上没有可用沙箱后端**（这是 win32 平台的真实限制）

## 6.5 审批策略对比

| 项目 | 策略 | 灵活度 |
|---|---|---|
| Claude Code | 逐次审批（走向沙箱化替代） | 低（93% 同意率说明失效） |
| Aider | 无审批（git 兜底） | — |
| Cline | 逐次 + autopilot 可选 | 中 |
| **Self-Agent** | **四档（gated/auto/strict/readonly）+ 白名单** | **高** |

Self-Agent 的四档策略是最灵活的：
- `gated`（默认）：WRITE/EXEC 要问
- `auto`：全放行（仅 CI）
- `strict`：全问
- `readonly`：只读，其余直接拒绝
- 加 `TOOL_AUTO_APPROVE` 白名单

---

## 6.6 安全设计的演进趋势

综合四家，编码 Agent 安全设计的演进方向：

1. **从逐次审批 → 沙箱化**（Claude Code 引领）：因为审批会失效
2. **从应用级 → OS 级隔离**（Self-Agent 已做到）：更硬的约束
3. **从单一策略 → 分档可配**（Self-Agent 已做到）：适应不同场景
4. **可回滚作为补充**（Aider 的 git 思路）：前置拦不住的，事后能救

**Self-Agent 在趋势 2、3 上领先，在趋势 4 上可借鉴 Aider**。

---

## 6.7 一个完整的故事：安全设计怎么演进

把这章串成一个故事：

> **第一代**（AutoGPT 那代）：无约束自主——跑偏、烧钱，证明不可行
> **第二代**（早期编码 Agent）：逐次审批——但 93% 同意率证明它失效
> **第三代**（Claude Code 沙箱化、Self-Agent 三层安全）：OS 级隔离 + 智能策略——既放手又安全
> **未来**：可回滚 + 前置拦截的智能组合

Self-Agent 站在第三代，而且三层安全的完整度是这四家里最高的。
