# 第 8 章：横向对比与给 Self-Agent 的借鉴

> 把前 7 章收口：六大编排框架横向对比，Self-Agent 的位置，以及借鉴建议。

## 8.1 六大框架横向对比大表

| 项目 | star | 编排引擎 | 状态管理 | 工具 | 记忆 | 多 Agent | 特色 |
|---|---|---|---|---|---|---|---|
| **LangGraph** | ~38.6k | Pregel 循环图 | channel+reducer+checkpointer | Tools+MCP | checkpoint+Store | 图节点 | 状态最严谨 |
| **OpenAI SDK** | ~18k | Agent 循环 | Sessions | function calling | Sessions | **handoffs** | 轻原语+guardrails |
| **AutoGen** | ~50-60k⚠️ | 事件驱动 | 对话历史+事件队列 | function calling | 对话历史 | **GroupChat** | 群聊（已维护模式） |
| **CrewAI** | ~34k | sequential/hierarchical | 任务结果链 | Tools+MCP | 短期/长期 | **角色化** | 直觉化 |
| **Pydantic AI** | ~18k | Agent+DI | 类型化 state | 类型安全 tools | 会话 | 弱 | 类型即契约 |
| **LlamaIndex** | （大仓） | 事件驱动+async | event/handler | tools+检索 | **RAG 强** | 工作流 | 检索最强 |
| **Self-Agent** | — | **LangGraph 图** | SQLite/PG checkpoint | 内置+MCP+Skill | 短/长/画像/日志 | **A2A** | 三层安全 |

> star 数为调研时点粗略值，会变，建议实时核对。⚠️ 表示维护模式。

## 8.2 Self-Agent 在六家里的位置

### 已有优势

1. **LangGraph 状态严谨性**：checkpointer/reducer/interrupt 是工业级 HITL 基础设施（第 1 章）
2. **A2A 标准化**：比 handoffs/GroupChat 更开放（第 7 章）
3. **三层安全**：编排框架里独此一家（其他都不管安全，那是编码 Agent 的事——见第 2 本书）
4. **四层记忆最丰富**：短/长/画像/日志各司其职

### 待提升

1. **无 hierarchical orchestrator**：长任务升级方向（CrewAI 第 4 章）
2. **无 guardrails 一等公民**：输入/输出校验（OpenAI 第 2 章）
3. **无结构化输出契约**：Agent 输出是裸文本（Pydantic AI 第 5 章）
4. **RAG 较简化**：单跳检索（LlamaIndex 第 6 章更强）

## 8.3 给 Self-Agent 的借鉴建议（汇总）

| 借鉴 | 来源 | 优先级 | 难度 | 收益 |
|---|---|---|---|---|
| **guardrails 一等公民**（输入/输出校验） | OpenAI SDK | ★★★ | 中 | 安全增强 |
| **hierarchical orchestrator**（长任务升级） | CrewAI | ★★ | 高 | 长任务能力 |
| **结构化输出契约**（result_type） | Pydantic AI | ★★ | 中 | 输出可靠 |
| **agent 行为评测**（Evals） | Pydantic AI 栈 | ★★ | 中 | 质量保证 |
| **更强 RAG**（多跳/混合检索） | LlamaIndex | ★ | 高 | 检索增强 |
| **checkpointer 反序列化安全** | LangGraph 漏洞警示 | ★★★ | 低 | 安全 |

### 重点解读

**guardrails 作为一等公民**（来自 OpenAI，最高优先级）：Self-Agent 安全主要在工具层，可以加一道独立的输入/输出校验层。比如：
- 输入：prompt injection 检测、敏感信息过滤
- 输出：PII 过滤、有害内容检测
放在 agent_node 入口/出口，不依赖工具层。

**hierarchical orchestrator**（来自 CrewAI）：Self-Agent 的「已知限制」是单层 ReAct。复杂任务可加一个 planner agent 拆解 + 子 agent 并行执行。这是较大改动，但能解锁「重构整个模块」这类大任务。

## 8.4 选型决策树（给要做新项目的人）

```
你的 Agent 需要中断恢复/复杂状态吗？
├─ 是 → LangGraph（Self-Agent 路线）
└─ 否 → 你的 Agent 需要多 Agent 协作吗？
    ├─ 是，且要标准化跨框架 → A2A（Self-Agent 路线）
    ├─ 是，但要直觉化同框架 → CrewAI
    ├─ 是，但要群聊讨论 → AutoGen（注意维护模式）
    └─ 否 → 简单 agent
        ├─ 要类型安全 → Pydantic AI
        ├─ 要 RAG 强 → LlamaIndex Workflows
        └─ 要最快上手 → OpenAI Agents SDK
```

**Self-Agent 的选择**：LangGraph（图）+ A2A（协议）。这是「内核要稳用图，扩展要活用协议」的组合，适合企业级、全功能、长期演进的项目。

## 8.5 这本书的核心结论

1. **编排四象限**：图/事件/流程/协议，各有取舍
2. **LangGraph 状态最严谨**：channel/reducer/checkpointer/interrupt 是工业级
3. **多 Agent 四范式**：群聊/接力/角色/委派，Self-Agent 选 A2A（标准化+解耦）
4. **AutoGen 教训**：高 star 不等于可持续，同步群聊扩展不动
5. **Self-Agent 内核选 LangGraph 是对的**：要图的严谨性；扩展选 A2A 是对的：要协议的开放性
6. **借鉴优先级**：guardrails > hierarchical > 结构化输出 > 更强 RAG
