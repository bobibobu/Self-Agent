# 第 2 章：Self-Agent 怎么补多模态（改造方案）

> 这章给具体改造方案——让 Self-Agent 能"看图"。不写代码（那是动手环节的事），但给出**精确到文件的改动点 + 关键设计决策**，让你（或未来的实现）照着做。

---

## 2.1 改造的核心：content 从 str 扩展成 content blocks

当前 `ChatMessage.content: str | None`（`app/llm/models.py:30`）。

**改造方向**：让 content 支持"字符串 或 content blocks 数组"，向后兼容。

### 数据模型改造（`app/llm/models.py`）

```python
# 新增一个 content block 类型
class ContentBlock(BaseModel):
    """多模态内容块。"""
    type: Literal["text", "image_url"]
    text: str | None = None                    # type=text 时
    image_url: dict | None = None              # type=image_url 时，{"url": "..."}
    # Anthropic 的 image 块格式不同，provider 层转换

class ChatMessage(BaseModel):
    role: Literal["system", "user", "assistant", "tool"]
    # content 支持两种形态：纯字符串（向后兼容）或 content blocks（多模态）
    content: str | list[ContentBlock] | None = None
    ...
```

**关键设计**：`content` 联合类型（str | list），保证现有纯文本代码不破坏。

## 2.2 改动点清单（按文件）

### ① `app/llm/models.py`——加 ContentBlock，content 改联合类型
- 新增 `ContentBlock` 模型
- `ChatMessage.content` 改成 `str | list[ContentBlock] | None`

### ② `app/llm/providers/openai_like.py`——透传 content blocks
- `_to_openai_messages` 要处理 content 是 list 的情况（每个 block 转 dict）
- 好消息：OpenAI SDK 原生支持 content blocks，几乎透传

### ③ `app/llm/providers/anthropic.py`——格式转换
- `_to_anthropic_messages` 要把 `image_url` 块转成 Anthropic 的 `image` 块格式
- 关键：base64 去 `data:image/...;base64,` 前缀，media_type 单独抽

### ④ `app/agent/nodes/bridge.py`——LangChain 消息转 content blocks
- `lc_to_chat_messages` 处理多模态 LangChain 消息
- LangChain 的 HumanMessage.content 也支持 list 格式

### ⑤ `app/api/upload_routes.py`——上传后能进对话
- 现在上传图片只返回 URL，要能让调用方把这个 URL 作为 image_url 块塞进 message
- 可选：新增一个 `/chat` 的字段 `image_urls: list[str]`，服务端自动拼成 content blocks

### ⑥ `app/api/routes.py`（或 schemas）——对话接口支持传图
- `/chat` 的请求体加可选 `images: list[str]`（URL 或 base64）
- 服务端把它们和文本拼成 content blocks 的 HumanMessage

## 2.3 关键设计决策

### 决策①：图片用 base64 还是 URL？

| 方式 | 优点 | 缺点 |
|---|---|---|
| **base64** | 不依赖公网可访问；本地图片也行 | 体积膨胀 33%；大图撑爆请求体 |
| **URL** | 体积小；省带宽 | 图片必须公网可访问；Self-Agent 本地的 /uploads/ 要暴露 |

**建议**：支持两种。用户上传的图（已在 `/uploads/`）用 URL（但要保证可访问或用 base64 兜底）；外部 URL 直接透传。

### 决策②：哪个模型支持多模态？

- `glm-4.5-flash`（Self-Agent 默认）——**纯文本**
- `glm-4.5v`——**视觉**（要切换 model）

所以要多模态时，配置层要能指定 vision 模型。可以在 config 加 `glm_vision_model: str = "glm-4.5v"`，有图片时自动切。

### 决策③：向后兼容

content 联合类型保证：纯文本场景（99%）行为不变，只有有图片时才走多模态分支。

## 2.4 改造后的使用流程

```
用户：「这张图里是什么？」+ 附图
  ↓
/api/upload 上传图 → 返回 url
  ↓
/chat 带 message="这张图里是什么？" + images=[url]
  ↓
服务端：拼成 HumanMessage(content=[
    {"type":"text","text":"这张图里是什么？"},
    {"type":"image_url","image_url":{"url":...}}
])
  ↓
agent_node → build_chat_request → ChatMessage(content=list[ContentBlock])
  ↓
openai_like provider：透传 content blocks（model=glm-4.5v）
  ↓
GLM-4.5V 看图回答
```
