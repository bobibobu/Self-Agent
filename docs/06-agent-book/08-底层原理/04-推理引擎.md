# 第 4 章：推理引擎（vLLM / SGLang / PagedAttention）

> Self-Agent 现在用云端 GLM API，不直接碰推理引擎。但如果未来本地化（自托管 DeepSeek/Qwen），这章决定选哪个引擎。
> 也是面试"常见推理优化手段"的答题弹药。

---

## 4.1 为什么需要推理引擎

直接用 HuggingFace transformers 跑模型，慢且吃显存（KV cache 碎片化、batch 效率低）。

**推理引擎**优化的是：显存利用率、吞吐量、延迟。核心技术：PagedAttention、continuous batching、prefix caching。

---

## 4.2 PagedAttention（vLLM 核心）

**借鉴 OS 的虚拟内存分页**。

### 灵感来源：OS 分页

OS 把内存分成固定大小的页，进程用虚拟地址，通过页表映射到物理页。好处：消除外部碎片、按需分配。

### KV cache 的碎片问题

传统推理引擎给每个请求预分配**连续的** KV cache 空间（按 max_seq_len）。问题：
- **内部碎片**：请求实际只用一半长度，另一半浪费
- **外部碎片**：请求结束释放的空间不连续，新的塞不进

### PagedAttention 的解法

把 KV cache 分成固定大小的 **block（页）**，每个请求的逻辑序列通过**块表**映射到物理块。
- 按需分配，用到哪分到哪
- 块可分散在显存任意位置
- 消除内外碎片，显存利用率大幅提升

**效果**：vLLM 吞吐量比 HuggingFace transformers 高数倍（论文数据）。

### 和 Self-Agent 的类比

LangGraph 的 checkpointer 也是"分步存档"（每节点跑完存一次），思路类似——把状态切成可管理的单元，按需持久化。不过 checkpointer 存的是对话状态，PagedAttention 存的是 KV 张量。

---

## 4.3 Continuous Batching（连续批处理）

传统批处理：一个 batch 里所有请求一起进、一起出。问题是：短请求要等长请求（head-of-line blocking）。

**Continuous batching**：请求可以**随时加入/离开** batch。某个请求生成完了立刻移出，新请求立刻加入，GPU 始终满载。

vLLM 和 SGLang 都用这个。

---

## 4.4 SGLang 的 RadixAttention

**vLLM 的 PagedAttention 解决"显存碎片"，SGLang 的 RadixAttention 解决"KV cache 复用"。**

### RadixAttention 原理

用**基数树（Radix Tree）**管理所有请求的 KV cache。基数树的每个节点代表一段 token 序列的 KV。

当新请求来时：
- 如果前缀在树里有 → 复用那段 KV
- 新增的部分追加到树

**这就是 SGLang 对 prompt caching 的优化**——天然支持前缀复用，对 Agent 的"多轮对话前缀相同"场景特别友好（[书⑥第 5 章](../06-进阶技术/05-其他新技术.md) 提到 SGLang 对多轮/工具调用据称快 2-3x）。

### vLLM vs SGLang

| 维度 | vLLM | SGLang |
|---|---|---|
| 核心创新 | PagedAttention（显存） | RadixAttention（KV 复用） |
| 强项 | 通用高吞吐 | 多轮/工具调用、结构化生成 |
| 适合 Agent | 好 | 更好（前缀复用天然） |

## 4.6 面试速答卡

> **Q：常见大模型推理优化手段？**
> A：KV Cache（避免重算历史）、PagedAttention（vLLM，KV 分页消除碎片）、Continuous Batching（请求动态进出 batch）、Prefix Caching（前缀 KV 复用）、量化（INT8/4 省显存）、Speculative Decoding（小模型投机大模型验证）、GQA（减少 KV 头数）、PD 分离。

> **Q：PagedAttention 借鉴了什么？**
> A：OS 虚拟内存分页。KV cache 分成固定 block，逻辑序列通过块表映射物理块，消除碎片、按需分配。

> **Q：vLLM vs SGLang？**
> A：vLLM 的 PagedAttention 解决显存碎片；SGLang 的 RadixAttention 用基数树管理 KV 实现前缀复用，对多轮/工具调用的 Agent 场景更友好。
