# 第 3 章：向量检索与索引（HNSW / IVF）

> Self-Agent 的长期记忆和 RAG 都靠向量检索（[书1第 7、11 章](../01-全书/07-记忆体系.md)）。这章讲透：为什么暴力检索慢、HNSW/IVF 索引怎么加速、为什么 Qdrant 比 pgvector 快。

---

## 3.1 向量检索的本质

把文本/记忆转成向量（embedding），检索就是"找最相似的向量"。

**相似度怎么算**：余弦相似度（向量夹角的余弦）或点积。Self-Agent 用余弦（[书1第 7 章](../01-全书/07-记忆体系.md)）。

**暴力检索（Brute Force）**：把 query 向量和库里所有向量逐一算相似度，排序取 top-K。复杂度 O(N·d)，N 是向量数，d 是维度。

**问题**：N 大了（百万级）就慢。所以要**索引**。

---

## 3.2 为什么需要索引

类比数据库的 B+ 树索引：不建索引要全表扫描，建了索引能快速定位。

向量索引也一样：不建索引暴力算，建了索引能**近似**快速找 top-K。

**关键认知**：向量索引基本都是**近似最近邻（ANN）**——不保证找到绝对最优的 top-K，但速度换精度，实际够用。

---

## 3.3 两大主流索引：HNSW 和 IVF

### HNSW（Hierarchical Navigable Small World）

**直觉**：像社交网络找人——从"名人"出发，沿着关系网一步步跳到目标。

**原理**（分层图）：
- 建一个**多层图**，每层是个"小世界"网络
- 顶层稀疏（少量节点，跨度大），底层密集（所有节点，精细）
- 查询时：从顶层某个节点出发，贪心跳到更接近 query 的邻居，逐层下降，到底层时就在 top-K 附近
- 类似"跳表"的思路，分层加速

**优点**：查询快（O(log N) 级）、召回率高。**缺点**：建索引慢、占内存（要存图结构）。

**谁用**：Qdrant（默认）、Milvus、Weaviate、pgvector（支持 hnsw）。

### IVF（Inverted File）

**直觉**：像图书馆分区——先把书按区域分桶，找书时只搜对应区域。

**原理**（聚类分桶）：
- 用 k-means 把向量聚成 k 个簇（"倒排"）
- 每个簇有个中心点
- 查询时：先找最近的 n_probe 个簇中心，只在这些簇里暴力搜
- 速度取决于 n_probe（搜几个簇），调大更准但慢

**优点**：建索引快、内存省。**缺点**：召回率受 n_probe 影响，不如 HNSW。

**谁用**：pgvector（ivfflat）、Faiss。

### 对比

| 索引 | 查询速度 | 召回率 | 建索引 | 内存 | 适合 |
|---|---|---|---|---|---|
| **HNSW** | 快 | 高 | 慢 | 大 | 查询密集、要准 |
| **IVF** | 中 | 中（可调） | 快 | 省 | 数据量大、要省内存 |

## 3.4 为什么 Qdrant 比 pgvector 快

（[书⑥第 6 章](../06-进阶技术/06-最强开源栈与缺口.md) 提到 Qdrant 比 Weaviate/Milvus 快 10-25%）

- **Qdrant 用 Rust**，无 GC 暂停，内存安全
- **专为向量优化**，HNSW 实现精良
- pgvector 是 Postgres 扩展，要兼容关系库的通用开销，HNSW 实现相对年轻

**但 pgvector 的优势**：如果已经用 Postgres（Self-Agent 就是），不用再起一个向量库，"够用"优先。

---

## 3.5 Embedding 模型：为什么 BGE-M3 强

embedding 质量直接决定检索质量。MTEB 排行（[书⑥第 6 章](../06-进阶技术/06-最强开源栈与缺口.md)）：
- **BGE-M3**（开源首选）：dense + sparse + 多向量，100+ 语言
- **代码检索**：Nomic Embed Code / Voyage Code 专项领先

Self-Agent 现在用 GLM embedding（或开发期哈希伪向量降级），生产可换 BGE-M3。

---

## 3.6 Reranker：为什么需要两阶段

向量检索是"粗排"（bi-encoder，快但粗），reranker 是"精排"（cross-encoder，慢但准）。

**两阶段**：
1. 向量库粗召 top-K（如 100）——快
2. cross-encoder 对这 K 个精排，取最终 top-N——准

**为什么 cross-encoder 更准**：它把 query 和文档拼一起过 Transformer，能捕捉细粒度交互；bi-encoder 是分别编码再算相似度，丢失交互信息。

Self-Agent 的 RAG 没加 reranker（[书⑥第 1 章](../06-进阶技术/01-幻觉.md) 列为改进点），加 bge-reranker 几乎免费提升精度。

## 3.8 面试速答卡

> **Q：向量检索为什么需要索引？**
> A：暴力检索 O(N·d)，百万级就慢。索引（HNSW/IVF）做近似最近邻（ANN），速度换精度。

> **Q：HNSW 怎么工作？**
> A：分层图，顶层稀疏大跨度、底层密集精细。查询从顶层贪心跳，逐层下降到底层 top-K 附近。O(log N) 级。

> **Q：为什么要 reranker？**
> A：向量检索是 bi-encoder 粗排（快但粗，丢失 query-doc 交互），reranker 是 cross-encoder 精排（拼一起过 Transformer，捕捉细粒度交互），两阶段平衡速度和精度。
