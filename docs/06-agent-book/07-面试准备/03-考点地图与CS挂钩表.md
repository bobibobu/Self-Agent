## 上篇：大厂 Agent 岗考点地图

### 一场 Agent 岗面试的结构

字节飞连 Agent 二面是「10 道项目题 + 6 道八股 + 1 道算法」——**项目深挖是绝对主角**，纯八股占比不高。这个结构对你极其有利：你的项目深度是最大差异化优势。

### ⭐ 算法题（你最焦虑的，给明确结论）

**会考，但是「入场券」不是「决胜项」。**

- **难度**：Easy-Medium 为主，Hard 极少。字节豆包三轮手撕是 Medium（合并区间 LC56、合并 K 链表 LC23、分割等和子集 LC416）
- **大模型岗专属手撕**（后端岗不考）：**手写 Softmax（数值稳定版）、Scaled Dot-Product Attention、Multi-Head Attention、LayerNorm/RMSNorm、FFN(SwiGLU)**
- **关键**：手撕模型组件写不出比 LeetCode 没做出影响更大——直接暴露 LLM 基础薄弱
- **过滤 vs 选拔**：算法是过滤器（过不了挂），项目深度才是选拔器（决定录用）

详见 [面试准备④](04-算法补救与路线图.md)。

## 下篇：CS 基础挂钩表

> 你的痛点：CS 基础没系统学，八股记不住。
> 解法：把每个 CS 知识点**挂在 Self-Agent 的真实代码场景上**——你不是在背「epoll 是什么」，而是在理解「我的 Agent 流式为什么用 asyncio 不用多线程」。

### 一、操作系统（OS）

| CS 知识点 | 一句话 | 在 Self-Agent 哪里挂钩 | 这么记 |
|---|---|---|---|
| **进程 vs 线程** | 进程独立内存空间，线程共享 | CLI 本地模式是单进程；沙箱用 bwrap 起**独立进程**隔离 | 沙箱要独立进程才隔离得开 |
| **asyncio/协程** | 单线程内并发，IO 等待时切换 | tools_node 用 `asyncio.gather` 并发跑多个工具（3 个各 2 秒共 2 秒非 6 秒） | Agent 调 LLM 是 IO 密集（等网络），协程最合适 |
| **select/poll/epoll** | IO 多路复用，epoll 是 Linux 高效版 | SSE 流式背后是 IO 多路复用；asyncio 事件循环依赖它 | 流式不卡，靠的就是 epoll |
| **文件锁** | 防并发写冲突 | SQLite checkpointer 多进程同时写会锁（README 已知限制：多副本 cancel_registry 失效） | 单文件 SQLite 的并发是短板 |
| **符号链接（symlink）** | 文件指向另一个路径 | 工作区禁闭**先 resolve 再判归属**——防 symlink 逃逸（[书1第 8 章](../01-全书/08-安全设计.md)） | 这个挂钩最直接，面试爱问 |
| **命名空间（namespace）** | 隔离进程视图（PID/网络/文件系统） | bubblewrap 沙箱用 `--unshare-pid/net/uts` 隔离 | bwrap 就是玩 namespace |
| **进程组** | 一起发信号 | Shell 工具超时**杀整个进程组**——只 kill 父进程会留孤儿（[书1第 9 章](../01-全书/09-编码Agent实战.md)） | pytest 起子进程，要杀组 |
| **Landlock（LSM）** | Linux 内核文件访问控制 | 沙箱的第二后端，限制可写范围 | 比 namespace 更细粒度的文件控制 |

### 二、计算机网络

| CS 知识点 | 一句话 | 在 Self-Agent 哪里挂钩 | 这么记 |
|---|---|---|---|
| **HTTP** | 请求-响应协议 | /chat 是 HTTP POST；A2A 是 JSON-RPC over HTTP | Agent 服务化的基础 |
| **SSE（Server-Sent Events）** | 服务端单向推送 | /chat/stream 用 SSE 流式（Web 端）；/chat/http-stream 用 NDJSON（CLI） | 真·token 流式的载体 |
| **TCP 粘包** | TCP 是流，没有消息边界 | NDJSON 流式要按换行切消息——这就是处理"粘包" | 流式协议设计要考虑分帧 |
| **HTTP/1.1 vs HTTP/2** | HTTP/2 多路复用 | 面试会问区别——HTTP/2 一个连接多请求 | 知道区别即可 |
| **TLS/HTTPS** | 加密传输 | JWT token 建议 HTTPS 传 | 认证安全的基础 |
| **DNS** | 域名解析 | A2A 的 Agent Card 放 `/.well-known/`，**类比 DNS 式发现** | A2A 发现机制的设计灵感 |
| **WebSocket vs SSE** | WS 双向，SSE 单向 | 流式用 SSE 不用 WS——因为只需要服务端→客户端推送 | Agent 回复不需要双向 |

### 三、数据库

| CS 知识点 | 一句话 | 在 Self-Agent 哪里挂钩 | 这么记 |
|---|---|---|---|
| **B+ 树索引** | 数据库索引结构 | Postgres 的会话/用户表索引 | 面试必问索引结构 |
| **事务/隔离级别** | ACID，防并发问题 | Postgres 存对话状态要事务可靠 | LangGraph 选 Postgres 不是 MySQL 的原因之一 |
| **MVCC** | 多版本并发控制 | Postgres 的 MVCC 支持高并发读 | 面试爱问 MySQL/PG 的 MVCC |
| **图数据库** | 关系是一等公民，邻接表存储 | 用户画像用 **Neo4j**——图遍历每跳 O(1)，关系型 3 跳 JOIN 崩 | **直接对应你的项目**（[书1第 7 章](../01-全书/07-记忆体系.md)） |
| **向量索引（HNSW）** | 近似最近邻图索引 | 长期记忆/RAG 的语义检索靠向量索引 | pgvector 支持 ivfflat/hnsw |
| **Redis 数据结构** | 字符串/哈希/zset 等 | 限流用 Redis 计数（[书1第 11 章](../01-全书/11-企业能力.md)） | zset 底层（跳表+哈希）面试爱问 |
| **MongoDB 文档模型** | 无 schema，文档存取 | 对话日志用 Mongo——形态多变、写多读少 | 多语言持久化选型理由 |

### 四、数据结构与算法

| CS 知识点 | 一句话 | 在 Self-Agent 哪里挂钩 | 这么记 |
|---|---|---|---|
| **哈希表** | O(1) 查找 | 工具注册表 `_registry: dict[str, BaseTool]` 按 name 查 | get_tool 是哈希查找 |
| **图（有向图）** | 节点+边 | LangGraph 的 StateGraph 本身就是图；Aider repo-map 用引用图+PageRank | Agent 编排=图遍历 |
| **树（AST）** | 源代码的树结构 | tree-sitter 解析代码成 AST（[书⑥第 6 章](../06-进阶技术/06-最强开源栈与缺口.md)） | 代码理解的根基 |
| **队列** | FIFO | asyncio 事件循环的任务队列；流式事件队列 | 流式=队列消费 |
| **字典序/前缀匹配** | 字符串前缀比较 | **Prompt caching 的精确前缀匹配**——KV cache 按 token 位置存，前缀变全失效 | 这是缓存题的核心 |
| **余弦相似度** | 向量夹角 | 长期记忆 embedding 检索（[书1第 7 章](../01-全书/07-记忆体系.md)） | 语义检索的数学基础 |
| **归并/快排** | 排序 | 面试必考；reranker 对 top-K 排序 | 手撕基础 |

## ⭐ LLM 专有八股（不是通用 CS，是大模型岗专属）

这些是后端岗不考、但 Agent 岗必考的。挂钩到你的项目：

| LLM 知识点 | 一句话 | 挂钩 | 对应书 |
|---|---|---|---|
| **Self-Attention** | `softmax(QK^T/√d)V`，√d 防梯度消失 | 每次调 LLM 底层就是这 | 手撕必考 |
| **KV Cache** | 缓存历史 token 的 K/V | **你做的 prompt caching 就是命中 KV cache**——这是挂钩点！ | [书⑥第 3 章](../06-进阶技术/03-缓存命中.md) |
| **prefill 慢/decode 快** | prefill 算力密集，decode 访存密集 | 首字延迟（context.build + 第一次 chat）主要卡 prefill | [书1第 12 章](../01-全书/12-完整链路拆解.md) trace |
| **温度/top-p/top-k** | 采样参数 | ChatRequest.temperature=0.7 | [书1第 5 章](../01-全书/05-LLM多协议抽象.md) |
| **PagedAttention** | KV cache 分页（像 OS 虚拟内存） | vLLM 的核心；类比 LangGraph checkpointer 分步存档 | [书⑥第 5 章](../06-进阶技术/05-其他新技术.md) |
| **LoRA** | 冻结原参，训低秩矩阵 A、B | 微调题——答"解决什么+场景"即可，别推公式 | 卡码笔记红线 |
| **RLHF/DPO** | RLHF=SFT+RM+PPO；DPO 绕过 RM | Hermes 反思是简化的"自我对齐"，不是真 RLHF | [书1第 11 章](../01-全书/11-企业能力.md) |

### KV Cache 这条挂钩（最重要，面试高频）

面试官问「KV Cache 是什么？」你这么答，把它和你的 prompt caching 改造连起来：

> "KV Cache 缓存的是 Transformer 每层每头对每个 token 算的 Key/Value 投影。推理时，每个新 token 的 attention 要看前面所有 token，如果前面 token 的 K/V 已算好就不用重算。**我在 Self-Agent 做的 prompt caching 改造，本质上就是让前缀固定，复用这部分已算好的 KV 张量——质量无损，只省钱和延迟。**"

这一答，把"懂 KV Cache 原理"和"有实战改造经验"同时证明了。
