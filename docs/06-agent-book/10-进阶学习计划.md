# 进阶学习计划：以 12 个开源项目为教材，把 Self-Agent 推向 2.0

> 书架前 8 本书解决的是「**读懂**」：概念、架构、别人的项目怎么做的。
> 这份计划解决的是下一层：「**写得出、讲得清**」——精读真实源码、动手改造本项目、把学到的东西变成能脱稿讲的分享。
>
> 教材就在本地：`D:\GitProject` 下的 12 个开源项目，每个都对应 Self-Agent 的一块短板或一个升级方向。
> 练兵场就是本仓库：**每个阶段必须落至少一个对 Self-Agent 的真实改动**。
>
> 📅 制定时点：2026-08-27 · 周期：约 6 个月（2026-09 ~ 2027-02）· 预算：每周 8~10 小时
> 📌 改造编号（如 #5、#16）均指 [改造路线图](06-进阶技术/07-速查与路线图.md) 中的行动清单

**结论**：不再缺「知道」，缺的是「源码级理解 + 落地经验」。所以本计划的三个铁律：

1. **以改代读**：每读一个项目，必须回答「Self-Agent 抄什么」，并至少落一次真实改动。
2. **读一寸写一寸**：源码笔记不写在别处，直接回填本书架（新增拆解章节），讲不出来的就是没读懂。
3. **先问题后代码**：打开一个项目前先写下 3 个想解决的问题，带着问题读，读完必须能回答。

## 4. 阶段 1：编排内核（2026-09，4 周）

> Self-Agent 的地基是 LangGraph，但一直只把它当黑盒用。这个月把黑盒打开。

### 带着这些问题读

1. 一次 `graph.invoke()` 从提交到输出，消息/状态在 Pregel 的 channel 里怎么流动？superstep 边界在哪？
2. Postgres checkpointer 的 put/get 到底存了什么？为什么「时间旅行」和 human-in-the-loop 恢复是免费的？
3. `interrupt()` 是怎么把图暂停又接回来的？和我们审批闸门的实现差在哪？
4. `with_structured_output` 在没有原生 JSON mode 的模型上是怎么兜底的？（直接服务 B 阶段结构化输出改造）

### 阅读路径（约 20h + 8h）

| 周 | 内容 |
|---|---|
| 第 1 周 | `langgraph/pregel/`：`main.py`（提交/调度循环）、`algo.py`（superstep 算法）；对照书③《01-LangGraph》 |
| 第 2 周 | `langgraph/graph/state.py` + `channels/`：StateGraph 构建、channel 写入策略（最后写入/累加）；`managed/`（共享值） |
| 第 3 周 | `libs/checkpoint-postgres/` + `interrupt` 恢复链路；`libs/prebuilt/` 的 `create_react_agent` 和我们手写的图对比 |
| 第 4 周 | `langchain_core`：`BaseChatModel` 的 `bind_tools` / `with_structured_output` / tool schema 生成；泛读 `langgraph/sdk-py`（平台化怎么做） |

### 动手 Lab（必须落仓）

- [ ] **Lab 1-2（衔接 B 阶段）**：借 `langchain_core` 的结构化输出兜底思路，给 GLM provider 的关键节点（计划、Hermes 反思）上 Pydantic 契约 + 失败重试
- [ ] **Lab 1-3（选做）**：把审批闸门从自研改成 `interrupt()` 原生实现对比，写一篇「两种实现的取舍」笔记

## 5. 阶段 2：记忆与 RAG 深水区（2026-10 ~ 11 上，5 周）

> 我们的 memory 是「短期状态 + 长期 Store + Neo4j 画像」，RAG 是「分块+向量+top-k」。两边都停在 baseline，这个阶段对标业界天花板。

### 带着这些问题读

1. 腾讯 L0~L3（会话原文 → 原子记忆 → 场景块 → 人设）每一层的提炼时机、去重策略、失败兜底是什么？
2. 它的单机版（SQLite）和服务版（TCVDB+Redis）为什么这么切？我们的多库架构该学哪半？
3. ragflow 的 deepdoc 对 PDF 表格/版式的处理，为什么是我们分块质量的数量级差距？
4. 混合检索（向量+全文+知识图谱）怎么融合排序？rerank 放在哪一层？

### 阅读路径（约 10h + 15h）

| 周 | 内容 |
|---|---|
| 第 1~2 周 | `TencentDB-Agent-Memory`：`README_CN.md` 全读 → `sdk/memory-core/` 提炼管线 → standalone/service 两形态差异；对照书⑤《04-Mem0》《05-记忆对比》 |
| 第 3 周 | `ragflow/deepdoc/`：文档解析管线（OCR/表格/版式）；`rag/nlp/`：分块与检索 |
| 第 4 周 | `ragflow/rag/graphrag/` + `advanced_rag/`：GraphRAG 与检索增强套路 |
| 第 5 周 | 把 `ragflow` 用 Docker 跑起来，灌一份自己的文档，体验端到端效果，记录差距 |

### 动手 Lab（对应路线图 #5/#6/#7/#8）

## 6. 阶段 3：Super Agent 实战（2026-11 中 ~ 12，6 周）

> 2026 年的天花板不是「一个更聪明的 ReAct」，而是「会编排自己、有技能库、可评测的 harness」。deer-flow 和 hermes-agent 是两个最值得抄的样本。

2. hermes 的 `trajectory_compressor.py` 压缩的是什么、什么时候触发？和我们「上下文压缩」模块的差异？
3. hermes 的 toolsets（能力打包分发）和我们的「工具注册表 + Skill 系统」怎么互相借鉴？
4. deepseek-harness 用什么指标刻画 agent 好坏？我们能不能给 Hermes 进化也立一套「评测集把关」（已知限制之一）？

### 阅读路径（约 15h + 15h + 6h）

| 第 1~2 周 | `deer-flow`：跑通 → `backend/app/` 编排主干 → `skills/` → `contracts/`（对照：它是 LangGraph 大型工程，直接可比） |

## 9. 每周节奏与学习方法

**节奏模板（每周 8~10h）**：工作日 4~5 天 × 1h（纯阅读/记笔记，通勤也行）+ 周末一次 3~4h（动手 Lab，整块时间留给写代码）。每周一顺手花 10 分钟处理 Renovate 的依赖 PR（本地 `uv run pytest` 过了就合，大版本按[升级记录](../04-guides/依赖升级记录.md)末尾的流程走）。

**源码阅读法**：
- 先跑起来再读（每个项目第一小时永远是跑 demo + 打日志）
- 自顶向下：README → 架构文档 → 入口文件 → 挑一条主干链路逐行走
- 用调试器跟一次完整请求，比读十遍代码记得牢
- 读到的每个「原来如此」立刻写进拆解笔记，链接到源码行

**费曼检验（每阶段一次）**：挑该阶段一个主题，不看任何材料写一篇能发给同事的短文 / 做 15 分钟分享。写不出来的段落 = 没学会的地方，回去重读。

**防弃坑机制**：
- 打卡表每周一行，状态只有 ✅ / 🔜 / ❌ 三种，❌ 必须写一句原因
- 连续两周 ❌ 触发降级：砍掉当周所有「选做」，只保主线 Lab
- 每阶段结束允许顺延一周，但顺延不能跨阶段叠加
