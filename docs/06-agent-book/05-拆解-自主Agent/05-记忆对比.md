# 第 5 章：记忆范式横向对比

> 这是本系列记忆部分的总结章。

## 5.2 核心区分：三种记忆哲学

所有记忆方案，按「**谁管理记忆**」分三种哲学：

### 哲学①：系统自动管理（Self-Agent、Mem0、AutoGPT）

系统负责抽取、存储、检索、注入。agent 是**被动消费者**。

- **Self-Agent**：系统检索 top-3 注入系统提示
- **Mem0**：系统抽取事实存向量库，查询返回
- **AutoGPT**：简单向量库存历史

**优点**：简单、可靠、通用。**缺点**：agent 不能主动「想起」、不智能。

### 哲学②：agent 自主管理（MemGPT/Letta）

agent 用工具**自己管理**记忆——检索、编辑、调度。

**优点**：智能（agent 知道自己需要什么）、自编辑。**缺点**：复杂、依赖 agent 能力、学习曲线陡。

### 哲学③：结构化记忆（MetaGPT、Aider repo-map）

不存「对话/事实」，存**结构化制品**（PRD/API/代码结构）。

- **MetaGPT**：存 PRD、设计文档、API 定义
- **Aider repo-map**：tree-sitter 解析代码结构

**优点**：精准（针对特定场景）、可消费。**缺点**：场景特化、不通用。

---

## 5.3 Self-Agent 在全景中的位置

Self-Agent 用的是**哲学①（系统自动）+ 四层结构**：

```
短期记忆（checkpointer）  ← 系统自动，原文消息流
长期记忆（Store）          ← 系统自动抽取+检索
用户画像（Neo4j）          ← 系统自动维护
对话日志（MongoDB）        ← 系统自动记录
```

### 在「丰富度」上靠前

四层记忆是这表里**最丰富**的——大多数方案只有一两层。

### 在「智能度」上居中

Self-Agent 是系统自动（哲学①），不是 agent 自管（哲学②）。比 AutoGPT 的简单向量库智能（有 Hermes 抽取），但不如 MemGPT 的 agent 自管。

### 在「结构化」上偏弱

Self-Agent 的记忆主要是自由文本事实，不像 MetaGPT/Aider 那样结构化。

## 5.5 记忆设计的几个关键权衡

### 权衡①：系统管 vs agent 管

- 系统管（Self-Agent/Mem0）：简单可靠，不智能
- agent 管（MemGPT）：智能，复杂依赖能力

**当前 LLM 能力下，系统管更实用**。未来 LLM 更强时，agent 管（MemGPT 模式）可能成为方向。

### 权衡②：自由文本 vs 结构化

- 自由文本（Self-Agent/Mem0）：灵活，检索靠语义
- 结构化（MetaGPT/Aider）：精准，但要预定义结构

**对话/用户事实适合自由文本，代码/交付物适合结构化**。

### 权衡③：单跳 vs 多跳检索

- 单跳（Self-Agent）：简单，找直接相关
- 多跳（Mem0 图查询）：强，找间接相关

**大多数场景单跳够用，复杂画像分析需要多跳**。

### 权衡④：原文 vs 摘要

- 原文（Self-Agent checkpointer）：完整，token 多
- 摘要：省 token，丢细节

**Self-Agent 的做法**：checkpointer 存原文，超长时临时压缩（全书第 3 章）。这是最务实的组合。

---

## 5.6 记忆领域的趋势

1. **从简单向量库 → 多层记忆**：AutoGPT 的单层向量库已不够，业界走向多层（Self-Agent 四层、Mem0 向量+图）
2. **从被动存储 → 主动管理**：MemGPT 的 agent 自管是前沿探索
3. **从自由文本 → 结构化**：MetaGPT/Aider 的结构化记忆在特定场景更精准
4. **从单 agent 记忆 → 共享记忆**：多 agent 协作需要共享记忆层（Mem0 的独立服务化方向）

**Self-Agent 在趋势 1（多层）领先，趋势 2-4 有借鉴空间**。
