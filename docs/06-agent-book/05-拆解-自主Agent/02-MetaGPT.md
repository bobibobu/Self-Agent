# 第 2 章：MetaGPT —— SOP 驱动的软件公司

> github.com/FoundationAgents/MetaGPT，~44-57k star（待核实，论文被引 3500+）。
> 把 **SOP（标准作业流程）** 编码进多 Agent 协作，**模拟一整个软件公司**。

---

## 2.1 它是什么

把人类团队的**标准作业流程（SOP）**编码进多 Agent 协作。模拟一整个软件公司：产品经理 / 架构师 / 项目经理 / 工程师 / QA。

**一行需求 → 完整项目**：端到端交付用户故事、竞品分析、数据结构、API、文档。

论文 arxiv 2308.00352，被引 3500+。

---

## 2.2 核心设计：SOP 驱动

把人类团队的工作流程（需求→分析→设计→编码→测试）固化成 agent 协作剧本。

### 为什么用 SOP

人类团队之所以能协作，是因为有**标准流程**——产品经理出 PRD，架构师据此设计，工程师据此编码。每个环节的输入输出是明确的。

MetaGPT 把这套流程编码进 agent 协作：
- 产品经理 agent → PRD（产品需求文档）
- 架构师 agent → 设计文档、API 定义
- 工程师 agent → 代码
- QA agent → 测试用例

---

## 2.3 ★ 角色分工 + 结构化产出

每个角色产出**标准化的中间制品**：

```
用户需求："做一个待办清单 app"
  ↓
产品经理 agent → PRD（含用户故事、功能列表、竞品分析）
  ↓
架构师 agent → 设计文档（数据结构、API 定义、技术选型）
  ↓
项目经理 agent → 任务分解（工程师要做什么、QA 要测什么）
  ↓
工程师 agent → 代码（按 API 定义实现）
  ↓
QA agent → 测试用例（按 PRD 验收）
```

**下游角色消费上游的制品**。这是 MetaGPT 的核心创新。

---

## 2.4 减少幻觉

通过 SOP 和结构化交付物约束 agent，比纯自由对话更可控。

### 为什么结构化能减少幻觉

- **输入明确**：工程师拿到的是明确的 API 定义，不是模糊的「做一个 app」
- **输出可验收**：QA 按 PRD 验收，不达标的能被发现
- **流程约束**：每个角色只做自己的事，不会越界瞎搞

---

## 2.5 ★ 流程先行 vs 协议先行（核心对比）

这是 MetaGPT 和 A2A（Self-Agent）最本质的区别。

| 维度 | MetaGPT（流程先行） | A2A（协议先行） |
|---|---|---|
| 协作定义 | 硬编码 SOP（产品→架构→工程→QA） | 只定义通信协议，流程由 agent 协商 |
| 灵活度 | 低（改流程要改代码） | 高（agent 自主决定怎么协作） |
| 可控性 | 高（流程可预测） | 中（依赖 agent 能力） |
| 适合 | 固定场景（软件开发） | 通用协作 |

### 权衡

- **MetaGPT 流程先行**：可控、可预测，但死板。换个场景（如做客服）就要重新写 SOP。
- **A2A 协议先行**：灵活、开放，但协作质量依赖 agent 能力。agent 不够聪明时协作质量差。

**Self-Agent 选 A2A** 因为定位通用（不只做软件）。MetaGPT 的 SOP 适合「软件开发」这种流程明确的垂直场景。

---

## 2.6 ★ 结构化中间制品的启发

MetaGPT 对「长期记忆该存什么」有重要启发：**存制品（PRD/API/设计文档）而不只是存「对话」**。

### 对比 Self-Agent 的记忆

| 方面 | MetaGPT | Self-Agent |
|---|---|---|
| 长期记忆存什么 | **结构化制品**（PRD/设计/API） | 从对话抽取的**事实**（Hermes） |
| 形态 | 完整文档 | 短文本（"用户是 Python 工程师"） |
| 用途 | 下游角色消费 | 注入系统提示个性化回答 |

### 借鉴价值

如果 Self-Agent 要做「能交付完整项目的 agent」（不只回答问题），MetaGPT 的制品化思路值得借鉴：
- 长期记忆除了存事实，可考虑存「制品」（计划、设计、决策）
- 多步任务的中间产物（update_plan 的计划、edit_file 的 diff）可作为结构化记忆

---

## 2.7 MetaGPT 的局限

- **场景窄**：「模拟软件公司」只适合软件开发，换场景要重写 SOP
- **流程死板**：SOP 写死，遇到流程外的情况不会变通
- **agent 数量固定**：角色是预设的，不能动态增减

---

## 2.8 给 Self-Agent 的启示

### 启示①：长期记忆可存制品

Self-Agent 的长期记忆存「从对话抽取的事实」（Hermes）。如果要做更强的长任务支持，可借鉴 MetaGPT，让记忆系统存**结构化制品**（计划文档、设计决策、关键 diff）。

### 启示②：SOP 作为可选模式

对于「软件开发」这种流程明确的垂直场景，Self-Agent 可加一个 SOP 模式——预定义角色和流程，而不是通用 ReAct。但这会牺牲通用性。

### 启示③：结构化交付物减少幻觉

Self-Agent 的 update_plan 是一种轻量结构化交付物。MetaGPT 的启示是：**更多环节都可以结构化**（不只是计划，还有设计、决策、验收标准）。
