# 第 13 章：外部世界怎么做的

> 这章是四本拆解书的**概览**。把市面上最重要的开源 Agent 项目/框架分门别类，讲清楚它们各自的核心设计、和本项目的关系。**深入拆解见四本拆解书。**

---

## 13.1 四大门派：编排哲学

所有 Agent 框架，按「怎么组织执行流程」可以分四派：

| 派别 | 代表 | 核心思想 |
|---|---|---|
| **图驱动** | LangGraph | 用状态图（节点+边+路由）描述流程 |
| **事件驱动** | LlamaIndex Workflows / AutoGen v0.4 | 用 event + handler 组织，消息驱动 |
| **流程驱动** | CrewAI / MetaGPT | 把人类工作流程（SOP）固化成剧本 |
| **协议驱动** | Self-Agent（MCP+A2A） | 靠标准协议接入生态，不绑框架 |

没有绝对优劣，是不同取舍。本项目选「图驱动（LangGraph）+ 协议驱动（MCP+A2A）」的组合。

## 13.2 编排型框架（Orchestration-first）

### LangGraph

- 地址：github.com/langchain-ai/langgraph · ~38.6k star（调研时点，待核实）
- **它是什么**：LangChain 团队的「低层级 Agent 编排框架」，专解「长时运行、有状态、可中断、可恢复」。**本项目编排引擎的直接对标物。**

核心设计：
1. **放弃 DAG，拥抱循环图**：Agent 必须「思考→行动→观察」循环。基于 Pregel/BSP 算法——每「超步」内并发执行就绪节点，超步结束统一合并状态。
2. **StateGraph + Channels + Reducers**：状态由命名 channel 组成，每个 channel 有版本号和 reducer。多节点并发写同一 channel 时 reducer 决定怎么合并，避免竞态。
3. **Checkpointer = 持久化 + 容错 + 中断**：每超步存档，可崩溃恢复、跨机器恢复。
4. **interrupt() = HITL 基础设施**：挂起后进程可真退出，新 invoke 从 checkpoint 续跑。支持 time-travel（回到历史节点重跑）。

**对 Self-Agent 的价值**：本项目直接用 LangGraph，所以理解 LangGraph 内部（channel/reducer/checkpointer/interrupt）对读懂本项目最有直接帮助。→ 深入见 [拆解② 编排框架](../03-拆解-编排框架/00-总览.md)

> ⚠️ 安全提示：2025 年 11 月 Check Point 披露过 SQLite/Redis checkpointer 的 RCE 漏洞链，自查注意反序列化安全。

### OpenAI Agents SDK（前身 Swarm）

- 地址：github.com/openai/openai-agents-python · ~18k star
- **它是什么**：OpenAI 官方生产级 Agent SDK，是 2024 教学项目 Swarm 的继任者。「少抽象、强原语、和 OpenAI 模型深度绑定」。

五个可组合原语：Agents / **Handoffs**（显式转交控制权）/ **Guardrails**（输入输出安全校验）/ Sessions / Tracing。

**对 Self-Agent 的对比**：handoff（控制权转移）vs A2A（任务委派），语义不同；guardrails 作为一等公民值得借鉴。→ 拆解②

### AutoGen（微软）

- 地址：github.com/microsoft/autogen · ~50-60k star（**维护模式**，重心转向新的 Microsoft Agent Framework）
- **它是什么**：多 Agent 对话框架，以 GroupChat（多 agent 围绕对话轮流发言）闻名。v0.4（2025 初）彻底重写为事件驱动 + 全异步。

**对 Self-Agent 的对比**：GroupChat（开会讨论隐喻）vs A2A（派工单隐喻）。v0.4 重写是「多 Agent 编排该用消息总线还是图」的真实案例。**维护模式提示：警惕「高 star 但已停更」。** → 拆解②

### CrewAI

- 地址：github.com/crewaiinc/crewai · ~34k star
- **它是什么**：**角色化（role-playing）多 Agent 框架**，灵感来自「人类组织协作」。核心抽象 Crew / Agent / Task。

**对 Self-Agent 的对比**：角色化（剧本角色）vs A2A（标准协议）。CrewAI 直觉化、A2A 标准化。hierarchical process 本质是内置 orchestrator/router。→ 拆解②

### Pydantic AI

- 地址：github.com/pydantic/pydantic-ai · ~18k star
- **它是什么**：**类型安全优先**的 Python Agent 框架，Pydantic 团队出品。和 mypy/pyright 深度集成，工具参数/返回值都 Pydantic 校验。

**对 Self-Agent 的对比**：如果重 Python 且强调「结构化+可维护」，Pydantic AI 的「类型即契约」值得借鉴。→ 拆解②

### LlamaIndex Workflows

- 地址：github.com/run-llama/llama_index
- **它是什么**：以 RAG/数据索引起家，2025 推出 Workflows 1.0——**事件驱动、async-first** 的多步编排。

**对 Self-Agent 的对比**：事件驱动 vs 图驱动 vs 协议驱动，三种哲学。LlamaIndex 在「检索增强记忆」上最成熟。→ 拆解②

## 13.3 编码 Agent（Coding-first，与本项目编码能力最对位）

> 这一类对 Self-Agent 至关重要，因为「工作区禁闭、审批、沙箱」正是编码 Agent 的核心安全设计。

### Claude Code（Anthropic，闭源）

- **它是什么**：Anthropic 官方命令行编码 agent，闭源。「agentic loop + 权限门 + 沙箱」的代表。
- 核心设计：极简 while 循环；权限门（数据显示用户对 **93% 的权限提示点了同意**）；**沙箱替代逐次审批**（「圈定一块地方随便干」）；harness 包裹 model。

**对 Self-Agent 的对比**：Self-Agent 用 bubblewrap/Landlock 做 OS 级沙箱，Claude Code 也走向沙箱化——**业界共识是 OS 级强制隔离 > 应用级权限提示**。本项目选择是正确方向且更彻底。→ 拆解①

### Cursor（闭源，VS Code fork）

- **它是什么**：AI 优先代码编辑器，**fork 自 VS Code**。
- 核心设计：fork 而非做插件（深度操控 UI/内核）；代码库 embedding 索引；自研模型 + 路由。

**对 Self-Agent 的对比**：Cursor 走「重 IDE 体验」，Self-Agent 走「协议化 agent 内核」。产品形态选择：把 agent 做进 IDE，还是把 IDE 做成 agent 的工具。→ 拆解①

### Cline（开源）

- 地址：github.com/cline/cline · ~58-65k star（2025 GitHub 贡献者增长最快，同比 4704%）
- **它是什么**：开源自主编码 agent，VS Code 扩展（也有 SDK/CLI），模型无关。
- 核心设计：**Plan/Act 双模式**（先规划再执行）；human-in-the-loop 审批；MCP 一等公民；可 headless 跑 CI。

**对 Self-Agent 的对比**：Plan/Act 分离值得借鉴；Cline「审批优先+可选 autopilot」vs Self-Agent「沙箱优先+审批」。→ 拆解①

### Aider（开源，研究最扎实）

- 地址：github.com/Aider-AI/aider
- **它是什么**：终端原生 AI 结对编程，git 原生（每改自动 commit），可接几乎任何 LLM。
- 核心设计：**repo-map**（tree-sitter 解析仓库 + 图排序选最相关代码）；**结构化 edit formats**（search/replace 块）；**Architect/Editor 双模型**（SOTA）。

**对 Self-Agent 的对比**：repo-map 是「长期记忆+代码理解」的优秀范式；Architect/Editor 是 Plan-and-Execute 在编码场景的精致版。**Aider 是最佳研究对象**——工程研究最扎实，代码量适中，直接对标编码能力。→ 拆解①

## 13.4 协议（Protocol-first，Self-Agent 核心栈）

### MCP（Model Context Protocol，Anthropic 2024）

- 规范：modelcontextprotocol.io · 最新 2025-03-26
- **它是什么**：连接 AI 应用与外部数据源/工具的开放标准。解决 M×N 集成爆炸。
- 核心设计：client-host-server 三层；三大原语（Tools/Resources/Prompts）；stdio/HTTP 传输；provider 无关；动态发现。

**对 Self-Agent 的对比**：MCP 是本项目工具层基石。重点对比「function calling 演进到 MCP」的历史脉络。→ 拆解③

### A2A（Agent2Agent，Google → Linux Foundation 2025）

- 地址：github.com/a2aproject/A2A · a2a-protocol.org
- **它是什么**：让不同框架/厂商的 agent 互相发现、通信、协作的开放标准。
- 核心设计：Agent Card（`/.well-known/agent-card.json`，DNS 式发现）；JSON-RPC 2.0 over HTTP + SSE；任务模型；与 MCP 互补。

**对 Self-Agent 的对比**：A2A 是多 Agent 层基石。重点对比四种多 Agent 范式（A2A 任务委派 vs LangGraph 图节点 vs AutoGen 群聊 vs OpenAI handoff）。→ 拆解③

## 13.5 早期自主 Agent（autonomous-first，历史意义）

### AutoGPT / AgentGPT / BabyAGI

- AutoGPT：github.com/significant-gravitas/autogpt · ~185k star（GitHub 史上增长最快仓库之一）
- **它是什么**：「自主 Agent」概念的源头。
- 核心设计：self-prompting 循环（模型自己给自己生成下一步任务）；任务列表 + 优先级（BabyAGI 标志性）；长期记忆（向量库）；文件系统 workspace。

**对 Self-Agent 的对比**：历史价值 > 工程价值。它们证明了「自主循环」可行，但暴露了**无约束自主性的问题**（跑偏、死循环、烧钱）。Self-Agent 的「审批+沙箱+工作区禁闭」正是对这一代教训的回应。→ 拆解④

### MetaGPT

- 地址：github.com/FoundationAgents/MetaGPT · ~44-57k star（待核实）
- **它是什么**：把 **SOP（标准作业流程）** 编码进多 Agent 协作，模拟一整个软件公司（产品经理/架构师/工程师/QA）。
- 核心设计：SOP 驱动；角色分工 + 结构化产出（PRD/设计文档/API）；减少幻觉。

**对 Self-Agent 的对比**：MetaGPT「流程先行」vs A2A「协议先行」。MetaGPT 的结构化中间制品思路对「长期记忆该存什么」有启发：存制品而不只是存对话。→ 拆解④

---

## 13.6 记忆层（专门的记忆项目）

### MemGPT / Letta

- **它是什么**：仿操作系统的**虚拟内存分页**——主上下文 + 归档层，agent 自己 page in/out，自编辑。
- **对 Self-Agent 的对比**：MemGPT/Letta 做的是**上下文管理**（让 agent 意识到上下文有限并主动管理），本项目的「短期/长期」对照：短期≈channel，长期≈分层。学习曲线陡但上下文管理极强。→ 拆解④

### Mem0

- **它是什么**：专门的记忆层/API，抽取式记忆 + 图/向量库。
- **对 Self-Agent 的对比**：Mem0 做的是**记忆存储/检索层**（抽取、存储、检索），易上手、基准性能好。→ 拆解④

## 13.8 最值得对比的五个点

1. **多 Agent 四范式**：AutoGen 群聊 / OpenAI handoff / CrewAI 角色 / A2A 任务委派——Self-Agent 选 A2A，要讲清楚为什么。→ 拆解②③
2. **安全演进**：Claude Code「沙箱替代逐次审批 + 93% 同意率」+ Self-Agent bubblewrap/Landlock，讲一个完整的安全设计演进故事。→ 拆解①
3. **记忆范式**：MemGPT 虚拟内存 vs Mem0 抽取层 vs Aider repo-map vs Self-Agent 四层——不同场景的记忆设计。→ 拆解④
4. **编排哲学**：图/事件/流程/协议四派，各有取舍。→ 拆解②
5. **协议演进**：function calling → MCP → A2A，工具生态平台化的脉络。→ 拆解③

## 13.9 关于 star 数和准确性

- star 数全部为「调研时点（2026 年 8 月）的粗略值」，不同来源有冲突处已标注「待核实」。**不要当精确值引用**，成书前去各 repo 实时核对。
- 设计思想来自各项目官方博客/规范/权威逆向分析，可信度较高。
- 凡无法确认的均标注，不编造。
