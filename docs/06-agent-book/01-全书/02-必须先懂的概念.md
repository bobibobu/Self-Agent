> 每个概念都附「本项目代码在哪」和「面试一句话」。

## 2.1 LLM（大语言模型）—— Agent 的大脑

Agent 的「大脑」。本项目支持三家：**智谱 GLM、OpenAI、Anthropic**。

关键点：三家的 API **长得不一样**——消息格式、工具调用格式、流式事件结构都不同。本项目用一层抽象（`app/llm/`）把这些差异藏起来，上层 Agent 代码只依赖统一接口，换一家改个配置就行（详见第 5 章）。

> 💡 **一个反直觉的事实**：大模型本身**没有「记忆」这种东西**。它是一个「输入文本 → 输出文本」的纯函数。所谓的「多轮对话」「记住上文」，全靠**每次把历史消息一起塞进输入**实现的。这是理解后面「短期记忆/长期记忆」的钥匙——记忆不是 LLM 的能力，而是**你的程序替它保管历史**。

---

## 2.2 Tool（工具）—— Agent 的手

大模型只会输出文字。所以我们给它一份「工具清单」，告诉它「你有这些能力可以用」。

清单里每一项是一份 **JSON Schema**，描述工具的名字、用途、参数。大模型看到清单后，想用某个工具时，就输出一个结构化调用请求：

```json
{"name": "read_file", "args": {"path": "main.py"}}
```

**程序**解析这个请求，真的去读文件，把内容塞回去给大模型。

> 🔑 复习第 1 章的钥匙认知：**大模型不调用工具，它只输出「想调用」的 JSON**。你的程序才是动手的那个。

本项目的工具在 `app/agent/tools/`（文件、Shell）和 `app/agent/plan.py`（计划）。第 6 章详讲。

## 2.3 ReAct 循环 —— Agent 的心跳

第 1 章详细讲过：思考 → 动手 → 观察 → 再思考的循环。

本项目实现：`app/agent/graph.py:306`（`agent` 节点 ↔ `tools` 节点的条件路由）。循环最多转 `AGENT_RECURSION_LIMIT` 次，防止无限循环。

## 2.4 LangGraph 与「状态图」

ReAct 循环我们**没有**用 `while` 写，而是用 **LangGraph** 描述成一张**状态图**：有节点（agent、tools）、有边（谁连谁）、有条件路由（要不要调工具）。

**为什么要这么绕？** 因为用 `while` 写的话，三样东西你得**自己从头实现**：

1. **状态持久化**：每次循环要把「当前状态」存下来，否则程序一退出就忘了。
2. **中途暂停再恢复**：审批时要停下来问你，你点同意后要能从原地继续。
3. **流式输出**：大模型逐字往外吐，你要实时转发给用户。

而 LangGraph 把这三样**免费送**了。代价是你要学一套「图」的概念（节点、边、reducer）。第 4 章会专门讲。

图的组装只有十几行：`app/agent/graph.py:306` 的 `get_compiled_graph()`。

## 2.5 ★ State（状态）与 Checkpointer

这是你最疑惑的地方，第 3 章会专门、彻底地讲。这里先建立直觉。

**State** 是在图里流转的「数据包」。本项目的 State 只有两个字段（`app/agent/state.py`）：

```python
class AgentState(TypedDict):
    messages: ...  # 对话历史（你说的、AI 说的、工具返回的）
    plan: ...      # 任务计划（多步任务的待办清单）
```

**Checkpointer** 是 LangGraph 的「存档机制」：**每走一步就把整个 State 存一次**。所以：

- 你下次用同一个 `thread_id` 继续聊，它记得之前说过什么（**短期记忆**）
- 审批时图暂停了，State 完整存着，你点同意后能**从暂停处原地继续**

本项目的 checkpointer 在 `app/memory/checkpointer.py:29`：
- 本地模式用 **SQLite**（单文件）
- 服务端用 **PostgreSQL**
- 都连不上就退化成内存（重启即丢）

> 🔑 **「记得上文」的本质**：不是 LLM 记得，而是 checkpointer 把历史消息存了下来，**下次调用时把历史一起塞进输入**给 LLM。LLM 每次都是「无状态」地看到完整历史，然后回答。

## 2.6 工作区（Workspace）—— Agent 能动手的范围

**默认是你 `cd` 进去的那个目录**。这是个**安全**概念。

为什么需要？因为大模型可能输出 `../../etc/passwd` 这种路径。所有文件操作都要先过一道检查——解析出来的真实路径必须**还在工作区里面**，否则直接拒绝（`app/workspace.py:63` 的 `resolve()`）。

```python
def resolve(self, path: str) -> Path:
    candidate = Path(path).expanduser()
    full = candidate if candidate.is_absolute() else self.root / candidate
    resolved = full.resolve()  # 展开 .. 和符号链接
    if resolved != self.root and not resolved.is_relative_to(self.root):
        raise WorkspaceError(f"拒绝访问工作区外的路径：{path}")
    return resolved
```

注意一个细节：**先 `resolve()` 再判断归属**。如果先判断再 resolve，一个指向工作区外的符号链接就能逃出去。第 8 章详讲。

## 2.7 审批闸门（人在回路）

写文件、跑命令这类**不可逆**的操作，执行前会停下来问你。

工具按「出错的后果可不可逆」分三档（`app/agent/registry.py` 的 `ToolRisk`）：

| 等级 | 例子 | 要不要问你 |
|---|---|---|
| `READ` 只读 | 读文件、搜索、算数 | 不问，错了重来即可 |
| `WRITE` 写 | 改文件、删文件 | **问** |
| `EXEC` 执行 | 跑命令、访问网络 | **问** |

**未声明风险的工具一律按最高风险（EXEC）处理**——这是故意的保守默认：新工具（尤其 MCP 发现来的第三方工具）没分级时，宁可多问一次，也不能默默放行一个可能删库的东西。

实现：`app/agent/nodes/tools_node.py` 的 `needs_approval()`，用 LangGraph 的 `interrupt()` 挂起整张图。

## 2.8 沙箱（Sandbox）

**审批管的是「你知不知情」，沙箱管的是「你点了同意之后，它最多能造成多大破坏」。**

为什么两个都要？举个真实的例子：

> 你同意它跑 `pytest`。但这个项目里有个恶意的 `conftest.py`，pytest 一启动就会读走你的 `~/.ssh/id_rsa` 发到外网。你点同意时想的是「跑个测试」，可没同意这个。

所以命令是在受限环境里跑的：**只能写工作区、看不见你的家目录、默认断网**（`app/sandbox.py`）。

两种 Linux 沙箱后端，分层降级：
- **bubblewrap**（`bwrap`）：容器级的命名空间隔离
- **Landlock**：Linux 内核 5.13+ 的文件系统访问控制

第 8 章详讲为什么这两层不能互相替代。

---

## 2.9 把八个概念串起来

用第 1 章的例子「读 main.py 然后加注释」串一遍：

1. 你的话进入 **State**（成为一条 `messages`）
2. 进入 LangGraph 图，去 **agent 节点**（思考）
3. 大模型决定调 `read_file`（**工具调用**），**ReAct 循环**走向 **tools 节点**（动手）
4. `read_file` 是只读，不审批；路径过 **工作区** 检查，读到内容
5. 内容塞回 State，**Checkpointer** 把这步的 State 存下来
6. 回到 agent 节点，大模型决定调 `edit_file`
7. `edit_file` 是写级，**审批闸门**触发 `interrupt()`，图挂起，State 落盘
8. 你按 `y`，图从原地恢复，命令在 **沙箱** 里执行
9. 大模型说「改好了」，不再调工具，循环结束

八个概念全用上了。下一章我们钻进最让你困惑的部分：**State 到底存的是什么**。
