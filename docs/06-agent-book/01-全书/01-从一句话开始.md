# 第 1 章：从一句话开始

> 目标：读完这章，你能用自己的话讲清楚「Agent 和直接调 API 有什么本质区别」。

---

## 1.1 直接调 LLM API 是什么样的

假设你要让大模型回答「北京天气怎么样」。最原始的做法：

```python
from openai import OpenAI
client = OpenAI()
resp = client.chat.completions.create(
    model="glm-4.5-flash",
    messages=[{"role": "user", "content": "北京今天天气怎么样？"}],
)
print(resp.choices[0].message.content)
# → "作为 AI，我无法获取实时天气……"（它不知道，只会说一段话）
```

这就完了。**输入一句，输出一句**。大模型本身：

- **没有手**：它不能上网查天气，不能读你电脑里的文件，不能跑代码。
- **没有记性**：这次问完，下次再问它不记得。
- **只能说话**：它的全部能力就是把一段文字变成另一段文字。

这种「你问它答」的模式，叫 **Chatbot（聊天机器人）**。Agent 和它的根本区别，就在于把「没有手」「没有记性」这两件事补上。

---

## 1.2 给 LLM 装上「手」：工具调用

大模型自己不能查天气，但**你的程序能**。问题是：程序怎么知道大模型「想」查天气？

答案是 **工具调用（tool calling）**。流程是这样的：

**第 1 步**：你预先告诉大模型，「你可以用这些工具」：

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询某个城市的实时天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名"}
                },
                "required": ["city"]
            }
        }
    }
]
```

这份清单告诉模型：「我手上有 `get_weather` 这个能力，它需要你提供一个 `city` 参数」。

**第 2 步**：你把用户的问题**和这份工具清单一起**发给大模型。

**第 3 步**：大模型不直接回答，而是输出一个**结构化的调用请求**（不是自然语言！）：

```json
{
  "role": "assistant",
  "tool_calls": [{
    "id": "call_abc123",
    "name": "get_weather",
    "arguments": {"city": "北京"}
  }]
}
```

注意：这里它**没有说话**，而是说「我想调用 get_weather，参数是 city=北京」。这是一段 JSON，不是「我觉得应该查一下北京天气」这种人话。

**第 4 步**：**你的程序**（不是大模型！）真的去执行 `get_weather("北京")`，拿到结果「晴 26°C」。

**第 5 步**：你把结果**再发给大模型**，告诉它「你刚才要查的天气结果是这个」：

```python
messages.append({
    "role": "tool",
    "tool_call_id": "call_abc123",
    "content": "晴，26°C"
})
```

**第 6 步**：大模型看到工具结果，这才输出最终的人话回答：「北京今天晴，26 度。」

这就是工具调用的完整循环。**大模型只负责决策（该不该用工具、用哪个、参数填什么），真正动手的是你的程序。**

> 🔑 **关键认知**：很多人以为「大模型调用了工具」。错。大模型**不能**调用任何东西——它只是个文本输入/文本输出的函数。所谓「工具调用」是**大模型输出一段 JSON，你的程序解析这段 JSON 去执行**。这个区分非常重要，后面所有设计都建立在它之上。

## 1.3 ReAct：让「思考」和「动手」循环起来

单次工具调用还不算 Agent。Agent 的精髓在于**循环**：

```
        ┌─────────────────────────────────┐
        │                                 │
        ▼                                 │
   ┌─────────┐   决定调工具     ┌─────────┐
   │ 思考     │ ──────────────→ │ 动手    │
   │ (问LLM) │                  │ (执行工具)│
   │         │ ←────────────── │         │
   └─────────┘   把结果给它     └─────────┘
        │
        │  决定不调工具了
        ▼
      回答用户
```

- 大模型说「我要读 main.py」→ 程序去读 → 把内容给大模型
- 大模型说「我要改 main.py」→ 程序停下来问你 → 你同意 → 程序去改 → 把结果给大模型
- 大模型说「我改好了」→ 不再要求调工具 → 输出最终回答 → 结束

这个「思考 ↔ 动手 ↔ 观察 → 再思考」的循环，叫 **ReAct**（Re-ason + Act）。

为什么非要循环？因为**真实任务没法一步完成**。「读 main.py 然后加注释」至少要：读 → 想 → 改 → 验证。每一步的结果都会影响下一步。一次性的大模型调用做不到——它只能根据「当前看到的东西」决定一次。

> 自主 Agent 的鼻祖 AutoGPT，本质上也就是把这个循环跑得「无人值守」。Self-Agent 的 ReAct 循环、LangGraph 的 ReAct agent、OpenAI 的 Agents SDK，底层都是同一个循环。**所有 Agent 框架的核心，都是把这个循环跑得稳、跑得安全、能记事。**

---

## 1.4 Self-Agent 里的 ReAct 长什么样

在这个项目里，ReAct 循环不是用 `while` 写的，而是用 **LangGraph** 描述成一张「状态图」（第 4 章会详细讲为什么）。核心组装只有几行，在 `app/agent/graph.py:282`：

```python
builder = StateGraph(AgentState)
builder.add_node("agent", agent_node)      # 「思考」节点：问大模型
builder.add_node("tools", tools_node)      # 「动手」节点：执行工具
builder.add_edge(START, "agent")           # 一进来先思考
builder.add_conditional_edges(             # 思考完，根据情况决定下一步
    "agent",
    should_use_tools,                      # ← 路由函数：要不要调工具
    {"tools": "tools", "end": END},
)
builder.add_edge("tools", "agent")         # 动手完，回去再思考
graph = builder.compile(checkpointer=checkpointer)
```

翻译成人话：

1. 进来先去 `agent` 节点，它问大模型「下一步干啥」
2. `should_use_tools` 这个函数看大模型的回答——
   - 如果大模型说「我要调工具」→ 去 `tools` 节点
   - 如果没说 → 结束
3. `tools` 节点执行工具，然后**回到** `agent` 节点继续思考

就这么简单。整本书后面所有的复杂机制（记忆、审批、沙箱、流式……）都是在这个骨架上加肉。**先记住这个骨架。**

## 1.5 小结

- **直接调 API**：输入一句、输出一句，大模型没有手没有记性。
- **工具调用**：大模型输出结构化 JSON，你的程序去执行——大模型只决策不动手。
- **ReAct 循环**：思考 ↔ 动手 ↔ 观察，反复直到任务完成。所有 Agent 的本质。
- **Self-Agent 的实现**：用 LangGraph 把 ReAct 描述成「agent 节点 ↔ tools 节点」的状态图。
