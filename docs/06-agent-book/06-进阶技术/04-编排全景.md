## 4.2 ★ Code-as-Agent 回归（重要反向潮流）

2025-2026 出现**回归纯代码、拒绝重框架**的思潮。

### 现象

**Claude Code、Cursor、Windsurf 的核心其实就是一个"极简 while 循环 + tool use"**。

- **Mihail Eric**（被广泛传播的观点）：所有 coding agent 平台的核心 loop "remarkably simple"——用户 prompt 循环驱动 tool use 而已
- **Karpathy**：倡导 "agentic engineering"，推崇极简 loop + eval 驱动的自改进

### 含义

框架（LangGraph 等）适合**复杂、需可观测/可恢复**的生产 agent；但**简单 agent 用纯代码 + 一个 while 循环往往更好**，避免框架黑盒和抽象泄漏。

### 2026 主流共识

> **"先别上框架，先写 loop，复杂了再上 LangGraph。"**

这印证了基础全书第 12 章的结论——**loop 简单，harness 难**。LangGraph 的价值在 harness（checkpointer/interrupt/可观测），不在 loop。如果你的 agent 不需要中断恢复、不需要复杂状态，纯 while 反而更清爽。

## 4.3 为什么本项目选 LangGraph（再确认）

本项目选 LangGraph 是对的，因为它需要：

- ✅ **中断恢复**（审批 interrupt → resume）
- ✅ **复杂状态**（messages + plan，reducer 合并）
- ✅ **可观测**（span 树）
- ✅ **跨模型**（GLM/OpenAI/Anthropic 都接）

如果只做个简单 chatbot（无审批、无状态、单模型），OpenAI SDK 或纯 while 更轻。

---

## 4.4 选型决策树（2026 做新项目怎么选）

```
你的 Agent 需要 interrupt/HITL 或复杂状态恢复吗？
├─ 是 → LangGraph 1.x（本项目路线）
└─ 否 → 你用什么模型？
    ├─ OpenAI 全家桶，想要最薄官方抽象 → OpenAI Agents SDK
    ├─ 已用 Pydantic/FastAPI，重类型安全 → Pydantic AI
    ├─ Google Cloud，偏好 code-first → Google ADK
    ├─ 微软生态/.NET → Microsoft Agent Framework
    ├─ 角色分工明确的多 agent → CrewAI
    ├─ Go 高性能 → Eino
    ├─ Java/Spring 企业级 → Spring AI Alibaba
    └─ 简单 agent → 别上框架，纯代码 while loop
```

## 4.5 和 Self-Agent 对比

本项目用 LangGraph 1.x，这是 2025.10 GA 的稳定版。在编排层，本项目**选型正确且不过时**。

但有两个可借鉴方向：

1. **Pydantic AI 的类型安全**：本项目用 Pydantic 做配置和 LLM 模型，但 agent 输出没强制类型。可借鉴 Pydantic AI 的 `result_type`（详见第 3 本书第 5 章）
2. **OpenAI SDK 的 guardrails 一等公民**：本项目安全在工具层，可借鉴 guardrails 做输入/输出校验层（详见第 3 本书第 2 章）
