## 7.1 ★ 三大难题速查表（面试核心）

| 难题 | 首选技术（必做） | 进阶（按需） | 高可靠场景 | 本项目（GLM）特别建议 |
|---|---|---|---|---|
| **幻觉** | **① RAG（baseline）+ ② 结构化输出约束 + ③ 函数调用 grounding** | **CRAG（检索兜底）/ Contextual Retrieval / Reranker** | **多 Agent critic 互验（跨厂商）+ CoVe 反思** | GLM 用结构化输出 + RAG；Claude 独享的 Citations API 不可用，用 prompt"必须引用来源编号"模拟 |
| **上下文漂移** | **① 滑动窗口摘要 + ② 外部 plan 记事板（update_plan）** | **Mem0 / LangGraph Store 长期记忆 + Plan-and-Execute 分解** | **Context Engineering 系统化设计（分层 prompt、按需加载）** | **把动态记忆/RAG 移出系统提示**，改用 Store/文件，每轮只注入最小集——既治漂移又救缓存 |
| **缓存命中** | **固定前缀结构：[冻结系统提示]+[冻结工具]+[历史追加]+[动态内容放末尾]** | **语义缓存（GPTCache，仅限 FAQ/客服类）** | **Anthropic cache_control 显式标 breakpoint（1h TTL）** | **GLM 是隐式缓存无法手标**，必须靠"前缀结构稳定"撞缓存；当前每轮拼动态系统提示是反模式；**预期命中率 < Claude（53% vs 91%）** |

## 7.2 各家 Prompt Caching 速查（面试常考）

| 厂商 | 支持 | 启用 | 命中折扣 | 最小前缀 | TTL |
|---|---|---|---|---|---|
| **Anthropic** | ✅ 最成熟 | 手动 `cache_control` | **省 90%** | 1024 tokens | 5min/1h |
| **OpenAI** | ✅ | **全自动** | 省 50% | 1024 tokens | ~5-10min |
| **DeepSeek** | ✅ | **全自动** | **省 90%** | 64-token chunk | 短时自动 |
| **GLM（智谱）** | ✅ | **隐式自动，无需 cache_control** | **省 50-80%**（多源不一致） | 文档未明确 | "合理时效性" |

**核心铁律**：只认**精确前缀匹配**，前缀改 1 个 token 整条缓存失效。

## 7.6 一句话总结全书

> **2026 年做 Agent，三大难题各有解：幻觉靠 RAG+结构化+grounding，漂移靠摘要+plan+Context Engineering，缓存靠固定前缀。**
>
> **编排不止 LangGraph——OpenAI SDK / Pydantic AI / 纯代码 while 都是主流。**
>
> **最强开源 Agent 的瓶颈不在框架（已达标），在底层模型 + 代码理解质量 + 产品体验。**
>
> **本 Self-Agent 项目最大的即时优化机会是 prompt caching——当前每轮动态拼系统提示是反模式，改成固定前置+动态后置，GLM cache 就能从 0 到有。**
