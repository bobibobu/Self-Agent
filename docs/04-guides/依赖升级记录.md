### 结构调整 ①：去掉 asyncpg，Postgres 只留 psycopg 一个驱动

**之前**：业务表（users / conversations）走 asyncpg 池，LangGraph checkpointer/store 走 psycopg 池——
一个进程两套驱动、两个池、两倍连接数（各 max 10）。

**之后**：`db_manager.postgres` 直接复用 `app/memory/pg.py` 的 psycopg `AsyncConnectionPool`
（autocommit + dict_row + prepare_threshold=0），`POSTGRES_POOL_MAX_SIZE` 管全部连接。

改动点：`app/db/manager.py`、`app/auth/user_service.py`、`app/services/session_service.py`、
`scripts/cleanup_test_data.py`、`app/core/config.py`（删掉 `postgres_dsn_asyncpg`）。

两个驱动的差异全是「静默失效」型，宽泛的 except 会把错误吞掉，表现成接口 200 但功能没生效：

| | asyncpg | psycopg |
|---|---|---|
| 占位符 | `$1` | `%s` |
| 受影响行数 | 解析命令状态串 `"DELETE 1"` | `cursor.rowcount` |
| 唯一约束冲突 | `asyncpg.exceptions.UniqueViolationError` | `psycopg.errors.UniqueViolation` |
| 取连接 | `pool.acquire()` | `pool.connection()` |
| 数组参数 | `ANY($1::text[])` 传 list | `ANY(%s::text[])` 传 `(list,)` |

`tests/test_pg_services.py` 用假池把每条 SQL 的占位符个数、参数、rowcount 处理钉死；
另外在真实 PostgreSQL 16（pgserver 内嵌）上跑了一遍 init.sql + migration + 注册/登录/会话增删改 +
LangGraph `AsyncPostgresSaver` 共用同一个池，全部通过。

### 结构调整 ②：Windows 必须用 SelectorEventLoop

psycopg 异步**不支持** Windows 默认的 ProactorEventLoop（连接时直接抛 `InterfaceError`）。
uvicorn 在 Windows 上不开 `--reload` 时用的正是 Proactor，桌面客户端内嵌的 uvicorn 也是。

这个坑以前就在（LangGraph 静默降级成 MemorySaver，[性能基准报告](性能基准报告.md) 里记过），
只是业务表走 asyncpg（兼容 Proactor），登录和会话还能用，所以没人当回事。
业务表并入 psycopg 后它会连带打挂登录、会话列表和对话历史，于是正式修掉：

- 新增 `app/core/eventloop.py`：`pg_loop_factory()`（Windows → Selector；其他平台与 uvicorn auto 一致）
- 桌面客户端 `uvicorn.Config(loop="app.core.eventloop:pg_loop_factory")`
- 服务端 Windows 无 `--reload` 时：`uvicorn app.main:app --loop app.core.eventloop:pg_loop_factory`
- 启动时 `check_loop_compatibility()` 检测到 Proactor 打 ERROR 并给出改法
- 脚本用 `asyncio.run(..., loop_factory=pg_loop_factory)`

**代价**：Windows 的 SelectorEventLoop 不支持 asyncio 子进程。
- shell 工具遇到 `NotImplementedError` 退到线程里跑 `subprocess.run`（超时只能杀直接子进程，Windows 没有进程组）
- MCP stdio client 由 mcp SDK 自带的 `FallbackProcess` 兜底，无需改动

**没有在 Windows 实机上验证**（开发机是 Linux）。测试里用 monkeypatch 模拟了 Windows 分支和
「循环不支持子进程」的分支。第一次在 Windows 上启动时，留意启动日志里的
「事件循环：SelectorEventLoop」和「事件循环兼容 psycopg」两行。

### 结构调整 ③：补上 httpx2 出站埋点

openai 3 / anthropic 1 / mcp 2 的默认 HTTP 客户端是 httpx2，而 `setup_telemetry()` 只挂了
`HTTPXClientInstrumentor`（只认 httpx）——LLM 请求的 HTTP span（状态码、429 重试）静默消失，
只剩手写的 `chat {model}` span。

`opentelemetry-instrumentation-httpx` 0.66b 起同包提供 `HTTPX2ClientInstrumentor`（PyPI 上单独的
`opentelemetry-instrumentation-httpx2` 是个 0.0.0 空包，别装）。现在两个都挂；
`tests/test_telemetry.py::TestOutboundHttpInstrumentation` 用真实 openai SDK 打本地假服务，断言产出 CLIENT span。

### 自动跟进：Renovate

根目录 `renovate.json`（已过官方 `renovate-config-validator`）：

- 每周一早上跑；Python 上界内更新只刷 `uv.lock`（`rangeStrategy: update-lockfile`），越过上界才改 pyproject
- minor/patch 按生态分组；OTel、langgraph/langchain 各自成组（版本号联动）
- **大版本**（含数据库镜像跨大版本）在 Dependency Dashboard 里勾选后才开 PR
- 国内镜像前缀通过 `registryAliases` 映射回 docker.io 查版本；Neo4j 限定在 5.x LTS

**还需要你做一次**：在 GitHub 仓库安装 [Renovate App](https://github.com/apps/renovate)；
Gitea 侧要自托管 Renovate（支持 `platform: gitea`）。项目目前没有 CI，Renovate 的 PR 合并前要本地跑 `uv run pytest`。

### 已有环境怎么升

```bash
uv sync                                   # Python 依赖（asyncpg 会被卸掉）
npm --prefix clients/web install && npm --prefix clients/web run build

cd infra
# 1) 换镜像之前，在还跑着 mongo:7 的容器上确认 FCV 是 "7.0"（不是就先设成 7.0）
docker exec -it selfagent-mongo mongosh -u selfagent -p selfagent123 --quiet \
  --eval 'db.adminCommand({getParameter: 1, featureCompatibilityVersion: 1})'

# 2) 拉新镜像、重建容器（数据卷保留；Jaeger 无状态）
docker compose pull
docker compose up -d
docker compose ps                         # 5 个服务都 healthy

# 3) Postgres 同大版本，只需把库里的 vector 扩展升到镜像自带版本
docker exec -it selfagent-postgres psql -U selfagent -d selfagent -c "ALTER EXTENSION vector UPDATE;"

# 4) MongoDB 在 8.0 上跑稳几天后再提 FCV（提了就不能回退到 7.0 镜像）
#   db.adminCommand({setFeatureCompatibilityVersion: "8.0", confirm: true})
```

Windows 上服务端不带 `--reload` 启动记得加 `--loop app.core.eventloop:pg_loop_factory`。

### 评估过但没做

| 方案 | 不做的原因 |
|---|---|
| MongoDB → Postgres JSONB | Mongo 只存 `conversation_events` 一类数据，换掉能少一个容器；但多库架构是项目的展示点之一，属于架构取舍，留给后续决定 |
| Redis → Valkey 9 | 只用到 INCR/EXPIRE，两者都兼容；Redis 8 是 AGPLv3，介意许可证再换，compose 注释里写了换法 |
| bcrypt → Argon2id | OWASP 首推 Argon2id，但要做「登录时校验旧哈希再重哈希」的双轨迁移，适合并入学习计划阶段 4 的安全还债 |
| mypy → pyrefly / ty | pyrefly 1.4 已 Stable、ty 仍 Beta；项目还没有 CI 跑类型检查，先不折腾 |
| PostgreSQL 17/18 | 16 支持到 2028-11；大版本要迁数据卷，等有明确收益（如 PG18 异步 IO）再做 |
| Python 3.13/3.14 | 3.12 支持到 2028-10；项目是 IO 密集型，free-threading 收益有限 |

## 怎么做下一次升级

1. **日常**：Renovate 每周一开 PR。范围内更新只动 `uv.lock` / `package-lock.json`，本地 `uv run pytest` 过了就合。
2. **大版本**：在 Dependency Dashboard 勾选 → 读对方 changelog 的 breaking 段 → 改上界 → 跑测试 → 在这里记一节。
3. **数据库镜像大版本**：先看 `infra/README.md` 的「版本与升级」，确认数据卷迁移路径再动。
4. **手动全量刷新**（Renovate 不可用时）：`uv lock --upgrade && uv sync && uv run pytest`，`npm outdated` 看前端。
