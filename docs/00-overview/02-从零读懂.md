
## 第 1 章：这个项目到底是什么

### 1.1 一句话

一个**能自己动手干活的 AI 助手**：你说"把这个函数的 bug 修了"，它会自己去读文件、
找问题、改代码、跑测试——而不是只告诉你"你应该这样改"。

### 1.2 它和「直接调 ChatGPT API」的区别

直接调 API：

```
你的问题 → 大模型 → 一段文字回答
```

Agent：

```
你的问题 → 大模型思考 → "我需要先看看 main.py"
                ↓
         程序真的去读了 main.py
                ↓
         把文件内容再给大模型 → "我发现问题在第 12 行，要改成..."
                ↓
         程序真的去改了文件
                ↓
         大模型 → "改好了，我跑了测试，通过"
```

关键差别：**大模型只负责思考和决策，真正动手的是程序**。这个"思考↔动手"的
循环叫 **ReAct**（Reason + Act）。

### 1.3 两种用法

| 形态 | 怎么跑 | 数据存哪 | 谁用 |
|---|---|---|---|
| **本地 CLI** | `selfagent` | 一个 SQLite 文件 | 你自己，在你的项目目录里 |
| **服务端** | `uvicorn app.main:app` | 4 个数据库 | 多个用户，通过网页或 HTTP |

两者**共用同一套 Agent 内核**——只是入口和存储不同。先理解本地形态，服务端形态
就是在它外面套了一层 HTTP + 认证 + 多租户。

## 第 2 章：必须先懂的 8 个概念

不用背，看懂意思就行。后面每章都会再用到。

### ① LLM（大语言模型）

Agent 的"大脑"。本项目支持三家：智谱 GLM、OpenAI、Anthropic。
代码里用一层抽象把它们的差异藏起来了（`app/llm/`），换一家改个配置就行。

### ② Tool（工具）

大模型只会输出文字，它自己**不能**读文件、跑命令。所以我们给它一份"工具清单"：

```
你可以用这些工具：
  read_file(path)          —— 读一个文件
  run_command(command)     —— 执行一条命令
  ...
```

大模型想读文件时，就输出一个**结构化的调用请求**（不是自然语言）：

```json
{"name": "read_file", "args": {"path": "main.py"}}
```

程序看到这个请求，真的去读文件，把内容塞回去给大模型。这套机制叫
**tool calling**（工具调用），是所有 Agent 的基础。

本项目的工具在 `app/agent/tools/`（文件、命令）和 `app/agent/plan.py`（计划）。

### ③ ReAct 循环

就是第 1.2 节画的那个循环，代码里长这样（`app/agent/graph.py:282`）：

```
        ┌──────────────┐
   ───→ │  agent 节点   │  问大模型："下一步干什么？"
        └──────┬───────┘
               │
        它要调工具吗？
          ┌────┴────┐
       是 │         │ 否
          ▼         ▼
    ┌──────────┐   结束，把回答给用户
    │ tools 节点│   真的去执行工具
    └────┬─────┘
         └──────→ 回到 agent 节点，把工具结果交给它
```

这个循环最多转 `AGENT_RECURSION_LIMIT` 次（本地模式默认 80），防止无限循环。

### ④ LangGraph 与「状态图」

上面那个循环，我们不是用 `while` 写的，而是用 **LangGraph** 把它描述成一张
**状态图**：有节点（agent、tools）、有边（谁连谁）、有条件路由（要不要调工具）。

为什么要这么绕？因为 LangGraph 免费送了三样东西：

1. **状态持久化**（下一条）
2. **中途暂停再恢复**（审批就靠它）
3. **流式输出**（逐字往外吐）

图的组装只有十几行：`app/agent/graph.py:282` 的 `get_compiled_graph()`。

### ⑤ State（状态）与 Checkpointer

图在跑的时候，有一个东西在节点之间传递，叫 **State**。本项目的 State 只有两个字段
（`app/agent/state.py`）：

```python
messages: 对话历史（你说的、AI 说的、工具返回的）
plan:     任务计划（多步任务的待办清单）
```

**Checkpointer** 是 LangGraph 的存档机制：每走一步就把 State 存一次。
所以：

- 你下次用同一个 `thread_id` 继续聊，它记得之前说过什么（**短期记忆**）
- 审批时图暂停了，State 存着，你点同意后能原地继续

本项目的 checkpointer 在 `app/memory/checkpointer.py:29`，本地模式用 SQLite，
服务端用 PostgreSQL，都连不上就退化成内存（重启即丢）。

### ⑥ 工作区（Workspace）

**Agent 能动手的范围**。默认是你 `cd` 进去的那个目录。

这是个安全概念：大模型可能输出 `../../etc/passwd` 这种路径，
所有文件操作都要先过一道检查——解析出来的真实路径必须还在工作区里面，
否则直接拒绝（`app/workspace.py:63`）。

### ⑦ 审批闸门（人在回路）

写文件、跑命令这类**不可逆**的操作，执行前会停下来问你。

工具按"出错的后果可不可逆"分三档（`app/agent/registry.py`）：

| 等级 | 例子 | 要不要问你 |
|---|---|---|
| `read` 只读 | 读文件、搜索 | 不问，错了重来即可 |
| `write` 写 | 改文件、删文件 | **问** |
| `exec` 执行 | 跑命令 | **问** |

### ⑧ 沙箱（Sandbox）

审批管的是"你知不知情"，沙箱管的是"你点了同意之后，它最多能造成多大破坏"。

为什么两个都要？举个真实的例子：

> 你同意它跑 `pytest`。但这个项目里有个恶意的 `conftest.py`，
> pytest 一启动就会读走你的 `~/.ssh/id_rsa` 发到外网。
> 你点同意时想的是"跑个测试"，可没同意这个。

所以命令是在受限环境里跑的：只能写工作区、看不见你的家目录、默认断网
（`app/sandbox.py`）。

## 第 3 章：一句话的完整旅程

这是全文最重要的一章。我们跟着一句真实的话走完全程：

> **"读一下 main.py，然后加个注释"**

### 全景图

```
你在终端敲下这句话
   │
   ▼
① CLI 接住 ──────────────────────────── clients/cli/selfagent_cli/localrepl.py:62
   │
   ▼
② 组装系统提示词 ────────────────────── app/agent/graph.py:204
   │  （身份设定 + 长期记忆 + 用户画像 + 知识库检索结果）
   ▼
③ 进入 LangGraph 状态图 ─────────────── app/agent/graph.py:342
   │
   ├─→ agent 节点：问大模型 ─────────── app/agent/nodes/agent_node.py:41
   │      大模型答："我要调 read_file(main.py)"
   │      同时逐字把思考过程流出来给你看
   │
   ├─→ 条件路由：有工具调用 → 去 tools 节点
   │
   ├─→ tools 节点 ──────────────────── app/agent/nodes/tools_node.py:176
   │      read_file 是只读 → 不用问你 → 直接执行
   │      路径先过工作区检查 ────────── app/workspace.py:63
   │      读到内容，塞回状态
   │
   ├─→ 回到 agent 节点：大模型看到文件内容了
   │      答："我要调 edit_file 加注释"
   │
   ├─→ tools 节点：edit_file 是「写」级 → ⏸ 停下来问你
   │      图在这里挂起，状态存进 SQLite
   │      ┌─ 需要你的确认 ─┐
   │      │ 工具：edit_file │  ← 你看到这个
   │      └────────────────┘
   │
   │   ...你按了 y...
   │
   ├─→ 从暂停处恢复 ────────────────── app/agent/graph.py:322
   │      真的去改文件（在沙箱里）
   │
   ├─→ 回到 agent 节点：大模型说"改好了"
   │
   └─→ 条件路由：没有工具调用了 → 结束
   │
   ▼
④ 你在终端看到最终回答
```

### 逐步细说

#### ① CLI 接住输入

`localrepl.py` 的 `_drive()` 函数。它做三件事：调用 `stream_agent()` 拿到一个
**事件流**，把事件渲染到终端，遇到审批请求就问你。

事件流长这样（一个个字典）：

```python
{"type": "token", "text": "我"}        # 大模型吐出的字，逐个来
{"type": "token", "text": "先"}
{"type": "tool_calls", "calls": [...]}  # 它决定调工具了
{"type": "tool_start", "name": "read_file"}
{"type": "tool_result", "name": "read_file", "content": "..."}
{"type": "approval_required", "tool": "edit_file", ...}   # 需要你确认
{"type": "done", "reply": "完整回答"}
```

#### ② 组装系统提示词

在真正问大模型之前，程序会拼一段**系统提示词**（`graph.py:204`）。
它不只是"你是一个助手"，而是把这一轮需要的所有背景都拼进去：

```
基础人设（你是 Self-Agent，工作原则是……）
  ＋ 已加载 Skill 的专属提示词
  ＋ 【知识库参考】从 RAG 检索到的相关文档  ← 只在指定了 kb_ids 时
  ＋ 【关于该用户的长期记忆】他是 Python 工程师…  ← 只在有 user_id 时
  ＋ 【用户画像】兴趣：机器学习；偏好：简洁回答
```

**一个重要设计**：这段提示词**不存进对话历史**。它每轮临时拼、临时用。

为什么？因为 State 里的 `messages` 是"追加"语义，如果每轮都往里塞一条系统提示，
第 10 轮时里面就有 10 份重复的提示词（每份还带着完整的记忆和知识库内容），
token 消耗会呈平方增长。所以它走 `config` 传给节点，用完即弃。

#### ③ agent 节点：问大模型

`agent_node.py:41`。核心是一次**流式调用**：

```python
async for chunk in llm.stream_chat(request):
    if chunk.content:
        writer({"type": "token", "text": chunk.content})   # 逐字吐给你
    if chunk.tool_calls:
        tool_calls_list = chunk.tool_calls                  # 工具调用决策
```

一次调用同时拿到"要说的话"和"要调的工具"。各家 API 返回的工具调用是**跨多个数据包
的碎片**，拼装逻辑在各 provider 里（`app/llm/providers/openai_like.py:166`）。

#### ④ 条件路由

`tools_node.py` 底部的 `should_use_tools()`：看最后一条消息有没有 `tool_calls`，
有就去 tools 节点，没有就结束。就这么简单——这就是 ReAct 循环的"路由器"。

#### ⑤ tools 节点：执行工具

`tools_node.py:176`。每个工具调用都走同一条流水线（`_run_one()`，第 89 行）：

```
1. 策略检查      readonly 模式下，写和执行直接拒绝
2. 审批检查      需要问用户吗？(needs_approval(), 第 61 行)
      ├─ 需要 → interrupt() 挂起整张图 ⏸
      └─ 不需要 → 继续
3. 找到工具      从注册表里按名字查
4. 执行          路径检查 → 沙箱包装 → 真的跑
5. 截断          结果太长就截断，防止撑爆上下文
6. 返回          ToolMessage 塞回状态，交给大模型
```

多个工具调用是**并发**执行的（`asyncio.gather`），三个各 2 秒的工具总共约 2 秒
而不是 6 秒。

#### ⑥ 审批中断与恢复（最绕的一步）

当工具需要审批时，`interrupt()` 会让**整张图停下来**。这不是普通的暂停——
LangGraph 会把当前状态完整存进 checkpointer，然后事件流自然结束。

```
第一次调用 stream_agent()
   ↓
   ...跑到一半...
   ↓
   interrupt() → 图挂起，状态落盘
   ↓
   吐出 {"type": "approval_required", ...} 事件
   ↓
   事件流结束（注意：不发 done，因为这轮还没完）

   ——— 你在终端按 y ———

调用 resume_agent(thread_id, {"approved": True})
   ↓
   LangGraph 从 checkpointer 读回状态
   ↓
   从 interrupt() 那一行**原地继续**，它返回你的决策
   ↓
   工具真的执行
   ↓
   继续走完剩下的循环
```

> ⚠️ **一个真实踩过的坑**：拿到 `approval_required` 事件就 `break` 退出循环，
> 会导致中断状态**还没写进 checkpointer** 就被中止，之后 resume 什么也不做
> 而且不报错——表现为"点了同意但什么都没发生"。
> 所以事件流**必须消费完**。`tests/test_local_mode.py` 里有专门的测试钉住这一点。

#### ⑦ 任务计划（多步任务才有）

如果任务需要三步以上，大模型会先调 `update_plan` 工具列个清单：

```
╭─ 任务计划 1/3 ─╮
│ ✔ 读懂 main.py │
│ ▶ 添加注释     │
│ ○ 验证结果     │
╰────────────────╯
```

这个清单**存在 State 里**，随 checkpointer 持久化。作用是给大模型一块外部记事板——
长任务走到第七八步时它不靠记忆，而是每轮都能读到"全局要做什么、现在做到哪"。

代码在 `app/agent/plan.py:105`。有个刻意的限制：同一时刻只允许一个步骤是
"进行中"，否则大模型会把所有步骤一次性标成进行中，清单就失去意义了。

## 第 4 章：数据都存在哪

### 本地模式（一个文件搞定）

```
~/.local/share/selfagent/projects/<项目路径的哈希>/
    ├── state.db          ← 对话历史 + 任务计划（SQLite）
    └── workspace.txt     ← 记录这个哈希对应哪个项目，方便排查
```

**按项目分库**：在 A 项目的对话不会串到 B 项目。换个目录就是干净的新开始。

### 服务端模式（四个数据库各司其职）

| 数据库 | 存什么 | 为什么用它 |
|---|---|---|
| **PostgreSQL** | 对话状态、长期记忆、用户、会话元数据 | LangGraph 官方支持，事务可靠，pgvector 能做向量检索 |
| **MongoDB** | 对话日志（每轮的完整事件） | 日志形态多变、写多读少，无 schema 正合适 |
| **Redis** | 限流计数 | 内存级速度，天然适合计数器 |
| **Neo4j** | 用户画像（兴趣、偏好） | "用户—兴趣—话题"本质是图，用关系库要疯狂 JOIN |

> 任何一个连不上都**不会**导致启动失败——只降级不崩溃。
> 比如 Mongo 挂了，对话照常，只是不记日志。

### 实验 1：看见 ReAct 循环

日志里会看到 `agent_node 调用 glm，消息数=N` 出现**两次**——
第一次它决定调 `get_current_time`，第二次它把工具结果转成人话。

### 实验 2：看见审批闸门

```bash

```

它会停下来问你。按回车（默认拒绝），观察它怎么处理被拒绝的情况——
它会收到"用户拒绝了此操作"并换个说法回应，而不是硬撞。

### 实验 3：看见工作区禁闭

```bash

```

它会拿到 `错误：拒绝访问工作区外的路径`。这是 `app/workspace.py:63` 在起作用。

## 第 7 章：常见问题

| 现象 | 原因与解法 |
|---|---|
| 启动报 `GLM_API_KEY 未配置` | `.env` 里填 key。智谱有免费额度 |
| 日志里 `回退 MemorySaver` | 连不上数据库。本地模式请确认 `STORAGE_BACKEND=sqlite`；服务端确认 Docker 起了 |
| 日志里 `已降级为哈希伪向量` | 没配 embedding key。长期记忆和 RAG 的检索结果会没有语义意义 |
| 命令输出带 `sandbox=none ⚠️` | 没有可用沙箱后端。Linux 装 `bubblewrap`，或确认内核 ≥5.13 支持 Landlock |
| 点了同意但没反应 | 事件流被提前 break 了。见 3.6 节 |
| 会话历史里有没问过的话 | 早期版本的测试污染。跑 `python scripts/cleanup_test_data.py --apply` |
| Web 端流式一片空白 | 旧版前端 SSE 解析 bug，已修。确认代码是最新的 |
| 任务跑到一半停了 | 撞上 `AGENT_RECURSION_LIMIT`。本地模式默认 80，可调高 |
