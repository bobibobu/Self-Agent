# B 阶段实战改造：Prompt 缓存命中 + 结构化输出契约

## 改造目标（两件事）

1. **让 LLM prompt caching 能命中**：当前系统提示每轮动态拼（含时间戳 + 动态记忆/RAG），前缀不固定 → GLM/OpenAI/Anthropic 缓存永远 miss。改造后让**真正固定的部分在最前面且每轮完全一致**。
2. **加结构化输出契约**：关键 agent 输出用 Pydantic 强制，杜绝格式幻觉。

## 关键发现（来自探索，决定方案可行性）

1. **时间戳是破坏前缀的元凶**：`SYSTEM_PROMPT` 末尾有 `{current_time}`，`_build_system_prompt` 每轮填真实时间 → 前缀漂移。
2. **不能把动态内容塞进 messages 末尾**（Explore 报告警告）：会触发三个陷阱——① `add_messages` reducer 会持久化它导致每轮累积；② `compress_if_needed` 会把它当 dialog 摘要掉；③ 多轮后堆积 N 条。
3. **resume 场景的隐藏事实**：当前 resume 续跑时 `_stream_graph` 新建的 config **不含 system_prompt**，所以 resume 后的 agent_node 调用其实**不带任何 system**（这对 caching 反而有利）。
4. **现有测试用 `_EchoLLM` 桩**绕过真实 API，加测试很方便。

## 方案设计

### 改造①：Prompt 缓存命中（核心，低风险路径）

**核心思路**：把"时间戳"从 system prompt 里移出去（放 config 侧通道传给 agent_node，作为一条**临时**的、不写回 state 的 SystemMessage 拼到对话末尾），让 system prompt 主体完全静态固定。

**具体改动**：

**a. `app/agent/prompts/__init__.py`** —— 去掉 `{current_time}` 占位
- 从 `SYSTEM_PROMPT` 删掉第 24 行的 `当前时间供参考...：{current_time}`
- 改成静态文本：「如需确切时间，请调用 get_current_time 工具」
- 这样 `SYSTEM_PROMPT` 主体完全静态

**b. `app/agent/graph.py:_build_system_prompt()`（74-110 行）** —— 去掉时间填充
- 删掉 `now = datetime.now(...)` 和 `base_prompt.format(current_time=now)`
- 调整拼接顺序：`SYSTEM_PROMPT`（静态） → Skill 提示词（半静态，启动后固定）→ 后面的 RAG/记忆/画像（动态，已在末尾）
- 拼接顺序固定为：**[静态 SYSTEM_PROMPT] + [Skill 提示词] + [动态 RAG/记忆/画像]**
- 前两段是稳定前缀（启动后不变），第三段是动态后缀

**c. 时间戳改走 config 侧通道**（不进 system prompt，也不持久化进 state）
- `_build_system_prompt_with_context` / `run_agent` / `_stream_graph`：把 `now` 时间戳放进 `config["configurable"]["current_time"]`
- `agent_node.py`：从 config 取 `current_time`，**临时**拼一条 SystemMessage（如「[当前时间：xxx]」）到 `messages` 列表末尾（和现有的 system_prompt 拼装一样，只用于这次 LLM 调用，不写回 state）
- 这样避开了 add_messages 累积和 compress_if_needed 摘要的陷阱——因为时间戳是 agent_node 局部变量里的临时消息，**不经过 state**

**d. Anthropic provider 加 cache_control（可选增强）**
- `app/llm/providers/anthropic.py`：`_split_system` 支持把 system 传成 list of blocks，静态段标 `cache_control: {"type":"ephemeral"}`（5min TTL）或 `1h` TTL
- 让 Claude 命中率到 90%+

**e. 可观测：trace 里加 cache 命中属性**
- `agent_node` 或 LLM span：记录 `gen_ai.cache.hit`（从 usage 里读 `cached_tokens` / `cache_read_input_tokens`，各家字段不同）

### 改造②：结构化输出契约

**核心思路**：让 agent 在"需要结构化输出"的场景（如 A2A 委托、工具决策）输出符合 Pydantic schema 的结果，而不是裸文本。

**具体改动**：

**a. `app/llm/models.py`** —— 加结构化输出支持
- `ChatRequest` 加可选字段 `response_format: dict | None`（JSON Schema）或 `result_type: type[BaseModel] | None`
- 复用已有的 `ToolDefinition` 机制（OpenAI 的 structured output 本质是受限的 tool calling）

**b. `app/agent/nodes/agent_node.py`** —— agent 节点支持 result_type（可选）
- 从 config 读 `result_type`，传入 ChatRequest
- 解析 LLM 输出为 Pydantic 对象（失败则降级为裸文本 + warning）

**c. 一个具体应用场景：A2A 委托返回结构化结果**
- `app/a2a/executor.py`：`SelfAgentExecutor` 包装时，给特定 task 指定 result_type，让输出结构化（而非现在的裸文本 reply）

### 测试更新（必须做，否则会破坏现有测试）

Explore 报告明确指出要更新：
- **`test_llm_still_receives_exactly_one_system_prompt`**：当前断言 `roles[0]=="system"` + `count("system")==1`。改造后时间戳走 config 作为临时 SystemMessage 拼到末尾——需要更新断言为「system 主体在最前」+ 允许末尾有时间戳的 system 消息（或把时间戳用非 system 角色承载，保持 count==1）。
- **`test_system_message_does_not_accumulate_in_state`**：只要时间戳走 agent_node 局部变量（不进 state），此断言不受影响。需验证。
- **telemetry 的 `context.build` 断言**：时间戳移出 `_build_system_prompt_with_context` 后，`context.build` span 仍在（RAG/记忆/画像还在里面），不受影响。需验证。

### 新增测试
- `tests/test_prompt_caching.py`：用 `_EchoLLM` 桩，断言**多轮调用的 system prompt 完全一致**（`seen_requests[0].messages[0].content == seen_requests[1].messages[0].content`），证明前缀固定。
- `tests/test_structured_output.py`：断言指定 result_type 时，LLM 输出被解析成 Pydantic 对象。
